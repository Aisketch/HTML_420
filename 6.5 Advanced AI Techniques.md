## КЛЮЧОВІ ЗНАХІДКИ

### 1. Few-Shot Learning: Оптимум 3-5 Examples

**Опис:** Anthropic documentation та ACM research підтверджують: 3-5 examples = optimal balance. XML tags (`<example>`, `<example_1>`) для розділення, H:/A: delimiters замість Human:/Assistant:.

**Чому важливо:** Few-shot з mobile-first patterns навчає Claude правильній responsive progression з першої спроби.

**Застосування:** Standard components: 3-4 examples | Complex: 4-5 | Design systems: 5-6 | Tailwind CSS preferred

### 2. Claude Artifacts: "No React" для Портабельності

**Опис:** "Build an artifact (no react)" генерує portable HTML/CSS/JS готовий для GitHub Pages. React = build dependencies. Artifacts ідеальні для rapid prototyping Single Page apps.

**Чому важливо:** Real-time preview дозволяє одразу тестувати responsive behavior без external tools.

**Застосування:** Prototyping 5-10 min | Client demos з publishable links | Workflow: Artifacts → Download → Deploy

### 3. Tailwind CSS Dominates Few-Shot

**Опис:** Tailwind 3-5x ефективніший vs custom CSS для few-shot: utility classes самодокументовані, responsive patterns standardized, mobile-first methodology вбудована.

**Чому важливо:** Base classes = mobile, prefixes = larger screens. Perfect alignment з mobile-first.

### 4. Chain of Thought: 13.79% Accuracy Boost

**Опис:** ACM research: CoT prompting improves accuracy by 13.79%. Stepwise з "next" keyword запобігає compounding errors. Plan Mode → Approval → Execution Mode.

**Чому важливо:** Desktop→Mobile First = multi-stage. Stepwise дозволяє verify кожен етап окремо.

### 5. Chrome DevTools AI: Integrated Gemini

**Опис:** Chrome Canary 131+ включає Gemini в DevTools. Right-click → "Ask AI". Direct access до DOM, styles, performance data.

**Чому важливо:** Розуміє mobile viewport context, аналізує responsive issues, Core Web Vitals.

### 6. Documentation Automation: 70-80% Time Savings

**Опис:** Readme-ai з Claude 3.5 + JSDoc Generator = comprehensive docs за хвилини. Комбінація: structure + mobile-first enhancement.

**Чому важливо:** AI-generated базові docs пропускають mobile specifics - enhancement додає context.

### 7. WCAG AI Auditing: 70-80% Issues Auto-Detected

**Опис:** Спеціалізовані accessibility prompts з WCAG 2.1 reference. AI identifies 70-80% issues automatically. "First rule of ARIA": native HTML preferred.

**Чому важливо:** Mobile accessibility = додаткові вимоги (44x44px targets, screen readers, gestures).

### 8. Core Web Vitals: AI-Driven Performance

**Опис:** Target: LCP ≤2.5s, INP <200ms, CLS ≤0.1. Chrome DevTools MCP дозволяє AI запускати performance traces, аналізувати bottlenecks.

**Чому важливо:** Mobile = обмежена compute, slower networks. AI виявляє mobile-specific issues.

### 9. Living Documentation: Docs-as-Code

**Опис:** Documentation generated з code automatically, evolves з кодом, CI/CD integrated. BDD scenarios = executable docs.

**Чому важливо:** Auto-generate responsive behavior docs, visual regression tests, accessibility reports. Завжди актуальні.

### 10. Cross-Browser AI: Compatibility Analysis

**Опис:** AI identifies gaps, suggests vendor prefixes, provides polyfills. Chrome Interop 2024: 87 overall.

**Чому важливо:** Mobile browsers (Safari, Chrome Mobile, Samsung Internet) мають різні quirks.

## BEST PRACTICES

### Practice 1: XML-Structured Few-Shot Templates

**Що:** XML formatting, 3-5 diverse examples, explicit mobile-first rules.

**Чому:** Чітке розділення context/rules/examples/task. Anthropic recommended approach.

**Код:**
```xml
<style_guidelines>
MOBILE FIRST: base → sm:640px → md:768px → lg:1024px
TOUCH: 44x44px minimum (py-3 px-4)
TEXT: text-base (16px) mobile, scale md: lg:
SPACING: p-4 mobile, md:p-6, lg:p-8
</style_guidelines>

<examples>
<example_1>
H: Mobile-first hero
A: <section class="py-20 md:py-32 px-4 bg-gradient-to-br from-primary to-primary-dark">
  <h1 class="text-4xl md:text-6xl font-bold text-white mb-6">Title</h1>
  <button class="bg-accent px-8 py-3 rounded-lg" style="min-height:44px">CTA</button>
</section>
</example_1>
</examples>

Now create: {TASK}
```

**Mobile:** Кожен example демонструє mobile → tablet → desktop progression, 44x44px targets, 16px+ text.

### Practice 2: "No React" Artifacts Workflow

**Що:** Prompt: "Build an artifact (no react)". Iterative: structure → features → test → deploy.

**Чому:** HTML/CSS/JS = portable, no build. React = dependencies.

**Код:**
```
Build an artifact (no react) for mobile-first landing page.

Features:
- Hero with CTA (full-width mobile, centered desktop)
- Feature grid (1/2/3 columns responsive)
- Contact form (mobile-optimized)
- Smooth scroll

Design:
- Mobile-first (320px-1920px)
- Touch targets 44x44px
- Primary: #1A4D2E
- WCAG 2.1 AA

Technical:
- Vanilla JS
- CSS Grid/Flexbox
- Lazy loading
- Production-ready
```

**Mobile:** Test на Claude iOS/Android apps, verify touch interactions.

### Practice 3: Chain of Thought Plan/Execute

**Що:** Plan Mode (analyze) → Approval → Execution Mode (implement). "Next" між steps.

**Чому:** Strategy review before implementation, prevents cascading errors.

**Код:**
```
[PLAN MODE] Refactor desktop-first to mobile-first.

CODE:
.container { width: 1200px; }
@media (max-width: 768px) { .container { width: 100%; } }

GOALS:
1. Mobile-first CSS (min-width)
2. Touch-friendly nav
3. WCAG 2.1 AA

Analyze WITHOUT implementing. Propose approach, risks, testing.

[Wait approval]

[EXECUTION MODE] Implement approved.
Step 1: Mobile base. Type 'next' when ready.
```

**Mobile:** Plan reviews responsive strategy, breakpoints, touch targets перед code changes.

### Practice 4: Automated Documentation Pipeline

**Що:** readme-ai → Claude enhancement → JSDoc → Storybook → CI/CD auto-update.

**Чому:** 70-80% time savings, living documentation synced з code.

**Код:**

**Mobile:** Enhancement додає mobile-specific documentation.
