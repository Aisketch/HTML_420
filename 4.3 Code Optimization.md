## 🔑 КЛЮЧОВІ ЗНАХІДКИ

### 1. HTML Minification: 17-60% зменшення + 80-85% з compression

**Детальний опис:** HTML minification через html-minifier-terser автоматично видаляє коментарі, collapse whitespace, мініфікує вбудовані CSS/JS. Комбінація з Brotli compression досягає 80-85% загального зменшення.

**Чому важливо для Mobile First:** На 3G (750Kbps): 1KB = ~11ms завантаження. First roundtrip (<14KB) критичний для mobile latency. FCP покращується на 100-300ms.

**Практичне застосування:** Інтегрувати в Vite/Webpack build pipeline, використовувати всі recommended опції (collapseWhitespace, minifyCSS, minifyJS), комбінувати з Brotli compression.

### 2. PurgeCSS: 70-96% зменшення CSS

**Детальний опис:** Аналізує HTML/JS файли та видаляє невикористані CSS класи. Tailwind: 259KB→9KB (96%), Bootstrap: 187KB→35KB (81%). Safelist механізм захищає динамічні класи.

**Чому важливо для Mobile First:** CSS render-blocking за замовчуванням. Великі frameworks блокують рендеринг на секунди на 3G. Critical для First Contentful Paint.

**Практичне застосування:** Обов'язково для Bootstrap/Tailwind, налаштувати safelist для framework класів (/^modal-/, /^carousel-/), додати до PostCSS pipeline. LCP +20-30%, FCP +25-35%.

### 3. Critical CSS: 40-60% покращення FCP

**Детальний опис:** Extraction і inline above-the-fold CSS (<14KB) в <head> забезпечує миттєвий рендеринг. Tools: Critical, Penthouse, Critters/Beasties. Решта CSS async.

**Чому важливо для Mobile First:** На 3G економія 940ms для 100KB CSS. TCP slow-start: перший пакет 14KB доставляє critical контент без додаткових roundtrips. Найбільший вплив на mobile FCP.

**Практичне застосування:** Critical або Beasties для SPA, mobile viewport (375x667) пріоритет, async load non-critical CSS через preload+onload trick.

### 4. JavaScript Code Splitting: 76% зменшення TTI

**Детальний опис:** Route-based та component-based splitting розбиває монолітний bundle. Dynamic imports з webpack magic comments. Vite/esbuild роблять автоматично.

**Чому важливо для Mobile First:** Mobile має обмежену пам'ять/CPU. 650KB JS блокує головний потік. Splitting до 150KB: TTI 23s→5.6s (Pinterest case).

**Практичне застосування:** React.lazy/Vue async для routes, manual chunks для vendor, prefetch наступних routes. Business impact: +40% engagement, +44% revenue.

### 5. INP замінив FID (Березень 2024)

**Детальний опис:** Interaction to Next Paint тепер Core Web Vital. Вимірює ВСІ взаємодії (не лише першу), target <200ms. ~600k сайтів перейшли з "passed" до "failed".

**Чому важливо для Mobile First:** Mobile CPU особливо вразливий до long tasks. INP виявляє responsiveness проблеми які FID пропускав.

**Практичне застосування:** Break up long tasks (>50ms), scheduler.yield(), defer non-essential JS, Web Workers для обчислень.

### 6. Vite: 10-100x швидше build

**Детальний опис:** 75k stars, 93M downloads/week. Native ES modules в dev, Rollup для production. Lightning-fast HMR, instant server start.

**Чому важливо для Mobile First:** Швидкий build дозволяє частіше ітерувати mobile оптимізації. Автоматичні best practices (tree-shaking, code-splitting, minification).

**Практичне застосування:** Мігрувати нові проекти на Vite, використовувати plugins для optimization, налаштувати code splitting. Build times: хвилини→секунди.

### 7. Real-World ROI: T-Mobile +60% конверсій

**Детальний опис:** T-Mobile (LCP -42%, конверсії +60%), Rakuten 24 (revenue +53%, A/B test), Pinterest (TTI -76%, revenue +44%), RedBus (mobile conversion +80-100%).

**Чому важливо для Mobile First:** Mobile = 50-60% traffic. 1s delay = -7% conversions. 53% users покидають сайти >3s load. Core Web Vitals корелюють з revenue.

**Практичне застосування:** Відстежувати Core Web Vitals (LCP <2.5s, INP <200ms, CLS <0.1), A/B тестування, RUM tools (web-vitals.js), кореляційний аналіз performance↔conversions.

### 8. AI-Assisted: 55% швидше розробка

**Детальний опис:** GitHub Copilot (55% faster), Cursor AI (superior context), Claude (advanced reasoning). Structured Chain-of-Thought +13.79% якості. AutoCode generation, debugging, refactoring.

**Чому важливо для Mobile First:** AI генерує оптимізований код з першого разу. Економія часу дозволяє фокус на UX. Automated code review виявляє issues.

**Практичне застосування:** GitHub Copilot /optimize в IDE, Claude з XML tags, Cursor Composer для multi-file refactoring, AI code review в CI/CD.

### 9. Render-Blocking Elimination: async/defer/preload

**Детальний опис:** CSS в <head> та JS без атрибутів блокують парсинг. Рішення: defer для DOM-залежних, async для незалежних (analytics), preload для критичних.

**Чому важливо для Mobile First:** Кожен render-blocking ресурс = network roundtrip (150-600ms на mobile). На 3G це секунди очікування.

**Практичне застосування:** Defer всіх non-critical scripts, async для analytics/ads, preload LCP image з fetchpriority="high", preconnect до third-party domains.

### 10. Accessibility-First: Zero Trade-offs

**Детальний опис:** Optimization НЕ повинна погіршувати accessibility. Lazy loading потребує announcements, focus management критичний. WCAG 2.2 (2023): новий 2.4.11 Focus Not Obscured, 2.5.8 Target Size (44px min).

**Чому важливо для Mobile First:** Mobile users = значний % з accessibility needs. Screen readers (VoiceOver, TalkBack) вимагають правильної структури. Touch targets 44x44px критичні.

**Практичне застосування:** Semantic HTML (button не div), ARIA live regions, focus management при route changes, skip links обов'язкові. Testing: axe/WAVE + manual screen readers.

## ⭐ BEST PRACTICES

### 1. Mobile-First Vite Configuration

**Що робити:** Налаштувати Vite з HTML/CSS/JS minification, code splitting, PWA capabilities, critical CSS.

**Чому працює:** Vite використовує Rollup з автоматичним tree-shaking, terser minification, optimal chunking. Single config контролює всі аспекти.

**Приклад коду:**
```javascript
// vite.config.js
import { defineConfig } from 'vite';
import { ViteMinifyPlugin } from 'vite-plugin-minify';
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    ViteMinifyPlugin({
      collapseWhitespace: true,
      removeComments: true,
      minifyCSS: true,
      minifyJS: true
    }),
    VitePWA({
      registerType: 'autoUpdate',
      manifest: {
        name: 'My Mobile SPA',
        short_name: 'MySPA',
        theme_color: '#ffffff'
      }
    })
  ],
  build: {
    minify: 'terser',
    terserOptions: {
      compress: { drop_console: true, passes: 2 }
    },
    cssMinify: 'lightningcss',
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],
          ui: ['@mui/material']
        }
      }
    }
  }
});
```

**Mobile First специфіка:** PWA для offline, code splitting за роутами, asset inline 4KB для FCP, CSS code split для parallel завантаження.

### 2. PurgeCSS Integration

**Що робити:** Інтегрувати PurgeCSS для видалення unused CSS з frameworks (Bootstrap, Tailwind).

**Чому працює:** Frameworks містять тисячі класів. PurgeCSS аналізує templates та залишає лише використані, досягаючи 70-96% reduction.

**Приклад коду:**
```javascript
// postcss.config.js
module.exports = {
  plugins: [
    require('@fullhuman/postcss-purgecss')({
      content: ['./src/**/*.{html,js,jsx,vue}'],
      safelist: {
        standard: ['modal-open', 'show', 'active'],
        deep: [/^data-bs-/, /^ais-/],
        greedy: [/^swiper-/, /^tooltip-/]
      },
      defaultExtractor: content => content.match(/[\w-/:]+(?<!:)/g) || []
    }),
    require('cssnano')({ preset: 'default' })
  ]
};
```

**Mobile First специфіка:** Safelist touch/mobile класи, test на real devices, viewport-specific patterns.

### 3. Critical CSS Extraction

**Що робити:** Екстрагувати CSS для above-the-fold, inline в <head>, async решта.

**Чому працює:** CSS render-blocking. Inline critical дозволяє миттєвий рендеринг без очікування. Економія 1-2 network roundtrips.

**Приклад коду:**
```html
<head>
  <style>
    /* Critical CSS < 14KB */
    body{margin:0;font-family:system-ui}
    .header{background:#fff;height:60px}
  </style>
  <link rel="preload" href="main.css" as="style" 
        onload="this.onload=null;this.rel='stylesheet'">
  <noscript><link rel="stylesheet" href="main.css"></noscript>
</head>
```

**Mobile First специфіка:** Priority mobile viewport (375px), test на 3G throttling, budget <14KB compressed.

### 4. JavaScript Code Splitting

**Що робити:** Route-based splitting з dynamic imports, manual chunking для vendor, intelligent prefetching.

**Чому працює:** Монолітні bundles блокують головний потік. Splitting завантажує тільки необхідний код, зменшуючи TTI з 20+ до <5 секунд.

**Приклад коду:**
```javascript
// React lazy loading
import { lazy, Suspense } from 'react';

const Dashboard = lazy(() => import(
  /* webpackChunkName: "dashboard" */
  /* webpackPrefetch: true */
  './pages/Dashboard'
));

function App() {
  return (
    <Suspense fallback={<Loading />}>
      <Dashboard />
    </Suspense>
  );
}
```

**Mobile First специфіка:** Initial bundle <200KB, per-route <50KB, test на 3G/4G, network-aware loading.

### 5. Resource Loading Strategy

**Що робити:** Використовувати preload, prefetch, preconnect, dns-prefetch для оптимізації critical rendering path.

**Чому працює:** Resource hints дозволяють браузеру завантажувати критичні ресурси раніше. Preconnect економить 100-500ms на з'єднання.

**Приклад коду:**
```html
<head>
  <!-- Preconnect third-party -->
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
  
  <!-- Preload LCP image -->
  <link rel="preload" href="hero.webp" as="image" 
        type="image/webp" fetchpriority="high">
  
  <!-- Preload critical font -->
  <link rel="preload" href="inter.woff2" as="font" 
        type="font/woff2" crossorigin>
  
  <!-- Prefetch next route -->
  <link rel="prefetch" href="/dashboard" as="document">
</head>
```

**Mobile First специфіка:** Media queries для mobile/desktop preloads, network-aware prefetching, prioritize mobile viewport LCP.

## ⚠️ ТИПОВІ ПОМИЛКИ

### 1. Не тестувати minified код
**Проблема:** Minification може порушити функціональність.  
**Рішення:** Генерувати source maps, test minified build локально, run E2E tests на production build.

### 2. Over-aggressive PurgeCSS
**Проблема:** Видалення динамічних classes.  
**Рішення:** Safelist patterns (/^btn-/, /^modal-/), test всі interactive components.

### 3. Ігнорування source maps
**Проблема:** Неможливо debug production issues.  
**Рішення:** Hidden source maps (sourcemap: 'hidden'), upload до Sentry.

### 4. Breaking layout з whitespace collapse
**Проблема:** collapseInlineTagWhitespace breaks spacing.  
**Рішення:** Set false, use conservativeCollapse: true.

### 5. Not separating Critical CSS
**Проблема:** Loading всього CSS blocks rendering.  
**Рішення:** Inline critical CSS (<14KB), async load решта.
