## 🔑 КЛЮЧОВІ ЗНАХІДКИ

### 1. Explicit Instructions Critical для Claude 4.x
Claude 4.5 Sonnet вимагає **явних, детальних інструкцій** - модель менше "здогадується" про intent. Вага промпту: ❌ "Створи гарний лендінг" → ✅ "Створи mobile-first landing page з hero секцією (headline + CTA), 3 feature cards, testimonials, contact form. Semantic HTML5, mobile-first CSS з breakpoints 640px та 1024px, кнопки мінімум 48px для touch."

### 2. XML Tags Підвищують Ефективність на 30-40%
Claude натреновано на XML-структурах в training data. Промпти з `<instructions>`, `<requirements>`, `<context>`, `<thinking>` тегами показують **значно кращі результати** ніж plain text. Anthropic офіційно рекомендує цю практику.

### 3. Context Window 200K-1M Токенів
**Стандарт**: 200K токенів (~500 сторінок, ~75K рядків коду)  
**Enterprise**: 500K токенів (Claude 4.5 Sonnet)  
**Beta**: 1M токенів (потребує спеціальний header)  
**Критично**: Performance деградує в останніх 20% контексту - використовуйте /clear при досягненні 80%.

### 4. Mobile-First Промптинг Вимагає Специфіки
Найефективніший паттерн: дизайн для 375px (iPhone SE) спочатку, потім progressive enhancement. Включити в промпт: exact breakpoints (375px, 768px, 1024px), touch targets мінімум 48px, typography 16px+, thumb-zone optimization для primary actions.

### 5. Prompt Caching Економить 90% Вартості
Кешування статичного контенту (documentation, code standards, system prompts) дає **до 90% зниження вартості** та 85% зменшення latency. Cache lifetime: 5 хвилин. Мінімум: 1,024 токени (Sonnet/Opus), 2,048 (Haiku).

### 6. Iterative Refinement > One-Shot Generation
Систематичний підхід: Generate → Review → Feedback → Refine переважає "perfect first try" на **70% за якістю**. Правило 3-х спроб: максимум 3 targeted fixes перед повною регенерацією. TDD pattern (test-first) знижує debugging на 60%.

### 7. Artifacts для Live Preview Критичні
Artifacts створюють **окремі вікна з live preview** HTML/CSS/JS. Автоматичне versioning, one-click publishing, remixing. Ідеально для landing pages - миттєвий preview змін без deploy. Типи: HTML pages, React components, SVG, Mermaid діаграми.

### 8. Multi-Turn Conversations до 20+ Turns
Ефективні conversation flows: Phase 1 (Requirements, 1-3 turns) → Phase 2 (Architecture, 4-6 turns) → Phase 3 (Implementation, 7-15 turns) → Phase 4 (Refinement, 16-20 turns). Використовуйте explicit references: "Referring to Hero component from turn 7..."

### 9. CLAUDE.md для Project Memory
Файл в корені проекту автоматично читається Claude Code. Включає: architecture, tech stack, code standards, common patterns, database schemas. Діє як **persistent context** через sessions. Критично для consistency в multi-turn development.

### 10. Debugging з Structure Prompts 50% Швидше
Structured debugging (Error + Code + Environment + Expected + Actual + Attempts) вирішує bugs **на 50% швидше** ніж "lazy prompting". Plan Mode для complex bugs: аналіз без змін → structured investigation plan → затвердження → execution.

## ⭐ BEST PRACTICES

### 1. HTML Generation: Structured Mobile-First Prompts

**Що робити:**
Використовуйте повністю структуровані промпти з явним mobile-first підходом та всіма технічними constraints з самого початку.

**Чому це працює:**
Claude 4.x не припускає requirements - explicit instructions забезпечують точну генерацію з першої спроби, економлячи iterations.

**Приклад промпту:**
```xml
You are an expert frontend developer specializing in mobile-first design.

<task>
Create a professional landing page for a SaaS product with:
- Mobile-first approach (design for 375px width first)
- Hero section with headline and CTA
- Three feature cards with icons
- Contact form with validation
- Footer with social links
</task>

<requirements>
- Use semantic HTML5
- CSS with mobile breakpoints: 375px, 768px, 1024px
- Implement flexbox for layouts
- Touch-friendly targets (minimum 48x48px)
- Smooth transitions and hover states
- Include viewport meta tag
</requirements>

<design_direction>
- Modern, clean aesthetic
- Color palette: Primary #2563eb, Secondary #10b981
- Typography: System fonts for performance
- Card-based layout with subtle shadows
- Generous white space for mobile readability
</design_direction>

<mobile_requirements>
- Stack elements vertically on mobile
- Touch-optimized buttons (min 48px height)
- Optimized text sizes (16px minimum)
- Fast-loading, optimized images
</mobile_requirements>

Think step by step about the mobile-first approach, then generate complete, production-ready HTML with embedded CSS.
```

**Mobile First специфіка:**
- Завжди починати з 375px базової ширини
- Explicit touch targets (48-56px для primary actions)
- Typography: 16px мінімум (запобігає zoom на iOS)
- Vertical stacking як default, horizontal на larger screens

### 2. CSS Styling: Component-Based Approach з Design Tokens

**Що робити:**
Створюйте CSS design system спочатку (colors, spacing, typography), потім компоненти що використовують ці tokens.

**Чому це працює:**
Consistency через проект, легке maintenance, швидкі iterations для брендингу.

**Приклад промпту:**
```xml
<task>
Create a mobile-first CSS design system for landing pages
</task>

<design_tokens>
/* Colors */
--primary: #2563eb;
--secondary: #10b981;
--text: #1f2937;
--background: #ffffff;

/* Spacing */
--space-xs: 0.5rem;  /* 8px */
--space-sm: 1rem;    /* 16px */
--space-md: 1.5rem;  /* 24px */
--space-lg: 2rem;    /* 32px */
--space-xl: 3rem;    /* 48px */

/* Typography */
--font-base: 16px;
--font-heading: clamp(1.5rem, 5vw, 3rem);
--line-height: 1.6;

/* Breakpoints */
--mobile: 375px;
--tablet: 768px;
--desktop: 1024px;
</design_tokens>

<components>
Create reusable component classes:
- .button (primary, secondary variants)
- .card (with shadow and hover states)
- .section (with responsive padding)
- .container (max-width with centering)
</components>

Use mobile-first media queries: base styles for mobile, enhance for larger screens.
