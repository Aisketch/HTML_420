## 🔑 КЛЮЧОВІ ЗНАХІДКИ

### 1.4.1 Sass/SCSS для масштабованих стилів

**1. Dart Sass з Compiler API — революція у performance (2024)**
- Ruby Sass офіційно deprecated, Dart Sass primary implementation
- Новий Compiler API забезпечує **35-800% прискорення компіляції**
- `sass-embedded` обов'язковий для production: 5.9s → 3.8s build time
- Vite 7.0+ використовує modern API за замовчуванням без додаткової конфігурації
- Single Sass instance замість spin up/down per file = massive efficiency gains

**2. 7-1 архітектурний патерн — proven standard для enterprise**
- Використовується Guardian, Financial Times, Yandex у production
- Структура: abstracts/base/components/layout/pages/themes/vendors + main.scss
- Чітке розділення відповідальності, легка навігація для великих команд
- BEM + Sass + 7-1 = золотий стандарт для масштабованості
- Mobile First через мікси з min-width media queries

**3. Performance обмеження критичні для mobile**
- **Inception Rule**: максимум 3 рівні вкладеності селекторів
- `mix()` function замість `darken()`/`lighten()` для передбачуваних результатів
- Fluid typography через `clamp()`: автоматичне масштабування без breakpoints
- Touch-friendly sizing: мінімум 44x44px відповідає Apple HIG та Material Design

**4. Native CSS vs Sass у 2024-2025 реальність**
- CSS нативно: nesting (90%+ browsers), custom properties, container queries, @layer
- Sass незамінний: mixins з logic/arguments, functions, conditionals (@if/@else), loops
- **Verdict**: Гібридний підхід оптимальний — CSS variables + Sass logic
- Sass потрібен для complex build-time transformations, CSS для runtime flexibility

**5. Mobile-specific Sass patterns**
- Responsive mixins з map-based breakpoints
- Touch-only та hover-only mixins для proper device targeting
- Fluid sizing functions для seamless scaling
- Safe area insets для notched devices (iPhone X+)

### 1.4.2 PostCSS та Autoprefixer

**6. PostCSS — transformational platform з модульною архітектурою**
- 200+ офіційних та community plugins для будь-якого use case

- Control comments для selective prefix disabling: `/* autoprefixer: off */`
- **Key insight**: Centralized Browserslist config shared across Autoprefixer, Babel, ESLint

**8. Essential PostCSS plugin ecosystem для Mobile First**

### 1.4.3 CSS Modules підхід

**11. CSS Modules — automatic scoping без runtime overhead**
- Генерує унікальні class names: `.button` → `.Button__button___2x3kl`
- **Vite**: `.module.css` files автоматично processed, zero configuration
- `localsConvention: 'camelCase'` для type-safe TypeScript imports
- **Named imports у ES2022+**: no restrictions на special characters
- Zero runtime cost vs CSS-in-JS (styled-components adds ~30KB)

**12. CSS Modules vs BEM vs CSS-in-JS — informed decision matrix**
- **CSS Modules**: Automation + compile-time + zero runtime + CSS caching ✅
- **BEM**: Manual discipline + global scope + no build step + legacy support
- **CSS-in-JS**: Max dynamic + runtime overhead (~30KB) + no CSS caching + bundle bloat
- **Data**: CSS Modules 8KB output vs styled-components 38KB (30KB difference)
- **Recommendation**: CSS Modules для SPAs, BEM для legacy, CSS-in-JS для enterprise apps з deep TS integration

**13. CSS Modules у Mobile First контексті**
- Media queries працюють natively inside modules без обмежень
- `composes` keyword для style inheritance між components
- `.module.scss` combination = Sass features + module scoping
- Responsive patterns через standard media queries, no special handling needed

**14. TypeScript integration для type safety**
- `typed-css-modules` auto-generates .d.ts definitions
- IntelliSense autocomplete для class names у VSCode
- Compile-time errors для typos у class references
- Enhanced developer experience у TypeScript projects

**15. Performance characteristics**
- Build-time processing = zero runtime JavaScript
- CSS output identical to hand-written, fully cacheable
- Code splitting works naturally with dynamic imports
- Smaller bundles than CSS-in-JS approaches

### 1.4.4 Critical CSS Generation

**16. Critical CSS — ключ до mobile performance optimization**
- Inlines above-the-fold CSS, eliminating render-blocking requests
- **Proven impact**: FCP improvement 20-40%, LCP reduction 0.2-1 second
- Critical size limit: **< 14KB compressed** fits first TCP roundtrip (10 packets)
- Особливо важливо для 3G/4G mobile networks з high latency

**17. Critters від Google Chrome Labs — optimal для SPAs 2024-2025**
- **No headless browser** = dramatically faster than alternatives (10-50x speedup)
- Inlines ALL used CSS (not just above-fold) = comprehensive coverage
- Automatic pruning: removes inlined CSS from lazy-loaded stylesheets
- Webpack plugin + Vite integration both available
- Font inlining/preloading built-in for complete optimization
- Maintained by Nuxt team as "Beasties" fork

**18. Critical CSS strategies для Single Page Applications**
- **Challenge**: Dynamic content makes traditional extraction difficult
- **Solution #1**: Component-based approach — critical CSS per route
- **Solution #2**: SSR/prerendering required for accurate extraction
- **Solution #3**: Route-based code splitting with separate critical bundles
- **Pattern**: Map routes → critical components → extract → inline

**19. Inline vs External Critical CSS trade-offs**
- **Inline** (recommended): Zero requests, fastest render, not separately cacheable
- **External** + `fetchpriority="high"`: Cacheable across pages, additional request
- **Hybrid** (best): Minimal inline (\u003c 5KB) + preload main critical CSS
- Always include noscript fallback для accessibility

### 1.4.5 PurgeCSS для оптимізації розміру

**21. PurgeCSS — індустріальний стандарт CSS optimization**
- **761,554+ weekly npm downloads**, 7,963 GitHub stars у 2024
- Static analysis approach: scans content → extracts selectors → removes unused
- **Typical reductions**: 67-99% CSS bundle size decrease
- **Real-world**: Tailwind 259KB → 9KB (96.5%), Bootstrap 325KB → 107KB (67%)

**22. Safelist strategies — критичні для dynamic classes**
- **Standard safelist**: exact matches + regex patterns для base classes
- **Deep safelist**: selectors + children (для framework components)
- **Greedy safelist**: entire chains (для animation libraries)
- **Critical**: Framework components (Vue/React), CMS content, JS-generated classes

**23. PurgeCSS vs alternatives — clear winner**
- **PurgeCSS**: Fastest + most flexible + modern framework support ✅
- **UnCSS**: Most accurate але slow (DOM emulation overhead)
- **PurifyCSS**: Deprecated, no longer maintained у 2024
- **Verdict**: PurgeCSS єдиний правильний вибір для production 2024-2025

Mobile data: Critical для budget device users

## ⭐ BEST PRACTICES

### 1.4.1 Sass/SCSS Best Practices

#### Practice #1: Mobile-First Responsive Mixins

```scss
// _mixins.scss
$breakpoints: (
  'mobile': 375px,
  'tablet': 768px,
  'desktop': 1024px,
  'wide': 1440px
) !default;

@mixin respond-to($breakpoint) {
  $value: map-get($breakpoints, $breakpoint);
  @if $value {
    @media (min-width: $value) {
      @content;
    }
  } @else {
    @warn "Breakpoint #{$breakpoint} not found!";
  }
}

// Usage
.hero {
  padding: 2rem 1rem;      // Mobile default
  font-size: 1.5rem;
  
  @include respond-to('tablet') {
    padding: 3rem 2rem;    // Tablet+
    font-size: 2rem;
  }
  
  @include respond-to('desktop') {
    padding: 4rem 3rem;    // Desktop+
    font-size: 2.5rem;
  }
}
```

**Чому працює**: Min-width queries = progressive enhancement, mobile styles як default = less code overrides

#### Practice #2: Touch-Friendly Component Patterns

```scss
@mixin touch-target($size: 44px) {
  min-width: $size;
  min-height: $size;
  display: inline-flex;
  align-items: center;
  justify-content: center;
}

@mixin hover-only {
  @media (hover: hover) and (pointer: fine) {
    @content;
  }
}

.btn {
  @include touch-target;
  padding: 0.75rem 1.5rem;
  
  @include hover-only {
    &:hover {
      transform: translateY(-2px);
    }
  }
  
  &:active {
    transform: scale(0.98);
  }
}
```

**Mobile First специфіка**: 44px = Apple HIG standard, hover detection = prevents sticky states

#### Practice #3: Fluid Typography Function

```scss
@function fluid-size($min, $max, $min-vw: 320px, $max-vw: 1200px) {
  $slope: ($max - $min) / ($max-vw - $min-vw);
  $intercept: $min - $slope * $min-vw;
  @return clamp(#{$min}, #{$intercept} + #{$slope * 100}vw, #{$max});
}

h1 {
  font-size: fluid-size(1.75rem, 3.5rem);
  // Scales 28px → 56px automatically
}
```

**Чому працює**: Native CSS clamp() + calculated viewport scaling = no breakpoints needed

### 1.4.2 PostCSS Best Practices

#### Practice #1: Complete PostCSS Pipeline

```javascript
// postcss.config.js
const isProd = process.env.NODE_ENV === 'production';

module.exports = {
  plugins: [
    require('postcss-import'),
    require('postcss-preset-env')({
      stage: 2,
      features: {
        'nesting-rules': true,
        'custom-media-queries': true
      }
    }),
    require('postcss-nested'),
    require('postcss-viewport-height-correction'),
    require('postcss-pxtorem')({
      rootValue: 16,
      propList: ['font*', 'margin*', 'padding*']
    }),
    require('autoprefixer'),
    isProd && require('cssnano')({
      preset: ['default', {
        discardComments: { removeAll: true }
      }]
    })
  ].filter(Boolean)
};
```

**Чому працює**: Correct order + conditional loading + mobile-specific fixes

#### Practice #2: Mobile Viewport Height Fix

```css
/* Input */
.hero {
  height: 100vh;
}

/* Output (postcss-viewport-height-correction) */
.hero {
  height: 100vh;
  height: calc(var(--vh, 1vh) * 100);
}
```

```javascript
// JavaScript
function setVH() {
  const vh = window.innerHeight * 0.01;

}
window.addEventListener('resize', setVH);
setVH();
```

**Mobile First специфіка**: Fixes iOS Safari address bar hiding = proper fullscreen layouts

### 1.4.5 PurgeCSS Best Practices

#### Practice #1: Comprehensive Safelist

```javascript
// purgecss.config.js
module.exports = {
  content: ['./src/**/*.{html,js,jsx,vue}'],
  safelist: {
    standard: [
      'active', 'show', 'fade',
      /^js-/, /^data-/,
      /^(sm|md|lg|xl):/  // Tailwind responsive
    ],
    deep: [
      /^modal/, /^dropdown/, /^tooltip/,  // UI components
      /^rte/, /^wysiwyg/,                 // CMS content
      /^v-/, /^el-/                        // Framework
    ],
    greedy: [
      /^animate__/, /^aos-/,               // Animation libs
      /-(enter|leave|appear)/              // Transitions
    ]
  }
}
```

**Чому працює**: Comprehensive patterns + framework coverage + dynamic class protection

#### Practice #2: Production-Only Execution

```javascript
// postcss.config.js
plugins: [
  process.env.NODE_ENV === 'production' && 
  require('@fullhuman/postcss-purgecss')({
    content: ['./src/**/*.{html,js,jsx}'],
    defaultExtractor: content => 
      content.match(/[\w-/:]+(?<!:)/g) || []
  })
].filter(Boolean)
```

**Mobile First специфіка**: Fast dev builds + optimized production = best DX

## ⚠️ ТИПОВІ ПОМИЛКИ

1. **Занадто глибока вкладеність Sass** → Max 3 рівні з BEM
2. **Відсутність Browserslist** → Centralized config у package.json
3. **Lazy-loading LCP image** → fetchpriority="high" замість loading="lazy"
4. **Багато Critical CSS** → Limit < 14KB compressed

6. **Відсутність noscript fallback** → Accessibility requirement
7. **PurgeCSS у development** → Production-only execution
8. **darken/lighten замість mix** → Unpredictable color results
9. **Немає тестування після PurgeCSS** → Visual regression required
10. **PostCSS version conflicts** → npm dedupe postcss
