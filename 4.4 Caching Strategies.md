# ПІДЕТАП 4.4.1: BROWSER CACHING HEADERS

## 🔑 КЛЮЧОВІ ЗНАХІДКИ

### 1. **Cache-Control - найпотужніший HTTP header для управління кешуванням**

HTTP header `Cache-Control` є основним механізмом контролю кешування в 2024-2025 роках, замінюючи застарілі `Expires` та `Pragma`. Він надає детальний контроль через директиви: `max-age` (час актуальності в секундах), `no-cache` (валідація перед використанням), `no-store` (повна заборона кешування), `public/private` (де можна кешувати), `immutable` (контент ніколи не змінюється).

**Чому важливо для Mobile First:** На мобільних пристроях з обмеженою bandwidth кожен зайвий запит коштує секунди. Правильний Cache-Control дозволяє завантажувати статичні ресурси лише раз, зменшуючи LCP на 60-80%.

**Практичне застосування:** Статичні assets (CSS/JS/images) з `max-age=31536000` (1 рік) + cache busting, HTML з `max-age=3600, must-revalidate` (1 година з перевіркою), API responses з `max-age=60, stale-while-revalidate=300`.

### 2. **ETag забезпечує ефективну валідацію без повторного завантаження**

ETag (Entity Tag) - це унікальний ідентифікатор версії ресурсу, зазвичай hash контенту. При наступних запитах браузер відправляє `If-None-Match: "etag-value"`, сервер порівнює і відповідає `304 Not Modified` якщо контент не змінився.

**Чому важливо для Mobile First:** На мобільних мережах економія bandwidth критична. ETag дозволяє перевірити актуальність ресурсу без передачі всього файлу - замість 500KB відправляється лише 304 header (~200 bytes).

**Практичне застосування:** Strong ETags (`"abc123"`) для byte-to-byte ідентичності, Weak ETags (`W/"abc123"`) для семантичної ідентичності. Використовувати разом з Cache-Control для оптимальної стратегії.

### 3. **Last-Modified як альтернатива ETag для часово-базованої валідації**

Last-Modified header вказує час останньої модифікації ресурсу. Браузер відправляє `If-Modified-Since`, сервер перевіряє timestamp і відповідає `304` якщо файл не змінювався.

**Чому важливо для Mobile First:** Простіший у реалізації ніж ETag, корисний для CMS систем та файлових серверів. Однак менш точний (точність до секунди).

**Практичне застосування:** Використовувати обидва headers (ETag + Last-Modified) для maximum compatibility. RFC9110 рекомендує завжди надавати обидва для 200 OK responses.

### 4. **Immutable directive для static assets з version hashes**

`Cache-Control: max-age=31536000, immutable` вказує браузеру, що ресурс НІКОЛИ не змінюється. Браузер пропускає revalidation навіть при hard refresh (Ctrl+F5).

**Чому важливо для Mobile First:** Найшвидший можливий performance - zero network roundtrips для кешованих assets. Особливо ефективно з versioned filenames (`app.abc123.js`).

**Практичне застосування:** Тільки для assets з content hash у filename. Ніколи для HTML або API endpoints. Підтримка: Chrome 61+, Firefox 49+, Safari 11+.

### 5. **Stale-While-Revalidate для background оновлення кешу**

`Cache-Control: max-age=3600, stale-while-revalidate=86400` дозволяє браузеру відразу показати stale content і одночасно оновити кеш у background.

**Чому важливо для Mobile First:** Instant response + fresh content. Users бачать сторінку миттєво, а наступний візит вже з актуальними даними. Best of both worlds.

**Практичне застосування:** Ідеально для API responses, user-generated content, feeds. Не для critical transactions (payments, bookings).

### 6. **Vary header для content negotiation**

`Vary: Accept-Encoding, Accept-Language` вказує, що кешовані версії залежать від цих headers. CDN створює окремі кеші для gzip/brotli, en/uk/pl.

**Чому важливо для Mobile First:** Мобільні браузери підтримують різні compression algorithms та мови. Vary забезпечує правильну версію для кожного пристрою.

**Практичне застосування:** `Vary: Accept-Encoding` (обов'язково для compressed assets), `Vary: Accept` (для різних formats), обережно з `Vary: User-Agent` (дробить кеш).

### 7. **Public vs Private caching для security**

`Cache-Control: public` - можна кешувати в CDN/proxies. `Cache-Control: private` - тільки у браузері користувача.

**Чому важливо для Mobile First:** Security на мобільних пристроях критична. Персональні дані НЕ повинні потрапляти в shared caches.

**Практичне застосування:** `public` для всіх static assets, `private` для user-specific content, `private, no-store` для sensitive data (bank info, medical records).

## ⭐ BEST PRACTICES

### 1. **Оптимальна конфігурація для Static Assets (CSS, JS, Images)**

**Що робити:**
```apache
# Apache .htaccess
<FilesMatch "\.(css|js|jpg|jpeg|png|gif|svg|webp|avif|woff2)$">
  Header set Cache-Control "public, max-age=31536000, immutable"
  Header set ETag "W/\"%{FILE_INODE}-%{FILE_SIZE}-%{LAST_MODIFIED}\""
</FilesMatch>
```

```nginx
# Nginx
location ~* \.(css|js|jpg|jpeg|png|gif|svg|webp|avif|woff2)$ {
  expires 1y;
  add_header Cache-Control "public, immutable";
  etag on;
}
```

**Чому це працює:**
- 1 рік кешування = maximum performance
- immutable = no revalidation overhead
- Public = CDN може кешувати
- ETag = fallback для validation

**Mobile First специфіка:**
- На 3G/4G мережах економія 5-10 секунд на сторінку
- Battery life покращується (less network radio usage)
- Data usage зменшується на 80-95%

### 2. **HTML Documents - Short TTL + Revalidation**

**Що робити:**
```javascript
// Node.js/Express
app.get('/', (req, res) => {
  res.setHeader('Cache-Control', 'public, max-age=3600, must-revalidate');
  res.setHeader('ETag', generateETag(content));
  res.setHeader('Last-Modified', new Date(fileStats.mtime).toUTCString());
  res.send(htmlContent);
});
```

**Чому це працює:**
- 1 година кешування для швидкого repeat visits
- must-revalidate забезпечує fresh content
- ETag дозволяє 304 responses

**Mobile First специфіка:**
- HTML зазвичай <50KB, revalidation дешева
- Users бачать instant load з кешу
- Сервер відповідає 304 за <50ms

### 3. **API Responses - Stale-While-Revalidate Pattern**

**Що робити:**
```javascript
// API endpoint
app.get('/api/data', (req, res) => {
  const data = getData();
  res.setHeader('Cache-Control', 'max-age=60, stale-while-revalidate=300');
  res.setHeader('ETag', hashContent(data));
  res.json(data);
});
```

**Чому це працює:**
- Fresh data протягом 1 хвилини
- Stale data допустима 5 хвилин (з background refresh)
- Zero perceived latency для users

**Mobile First специфіка:**
- API calls - найдорожчі на mobile (latency + battery)
- Users толерантні до slightly stale data якщо instant
- Background refresh не блокує UI

### 4. **No-Cache для Dynamic Personalized Content**

**Що робити:**
```javascript
// User-specific dashboard
app.get('/dashboard', requireAuth, (req, res) => {
  res.setHeader('Cache-Control', 'private, no-cache, must-revalidate');
  res.setHeader('ETag', generateETag(userContent));
  res.render('dashboard', userData);
});
```

**Чому це працює:**
- no-cache force validation (але дозволяє 304)
- private забезпечує no CDN caching
- ETag робить validation ефективною

**Mobile First специфіка:**
- Personalized content часто small (<200KB)
- 304 responses швидкі навіть на 3G
- Security важливіша за ultra-fast loads

### 5. **Sensitive Data - No-Store для Zero Caching**

**Що робити:**
```javascript
// Payment/banking endpoints
app.post('/api/payment', (req, res) => {
  res.setHeader('Cache-Control', 'private, no-store, no-cache, must-revalidate');
  res.setHeader('Pragma', 'no-cache'); // HTTP/1.0 compatibility
  res.setHeader('Expires', '0');
  processPayment(req.body);
});
```

**Чому це працює:**
- no-store = NO caching anywhere
- Triple-layer protection (Cache-Control + Pragma + Expires)
- Кожен request свіжий з origin

**Mobile First специфіка:**
- Payment forms завжди over HTTPS
- Slower = acceptable для security-critical operations
- Clear cache after transaction

## 💻 CODE SNIPPETS & TEMPLATES

### Snippet 1: Complete Cache Strategy для Node.js/Express

```javascript
const express = require('express');
const crypto = require('crypto');
const app = express();

// Middleware: Cache Strategy
const cacheStrategy = (type) => (req, res, next) => {
  const strategies = {
    'static': {
      'Cache-Control': 'public, max-age=31536000, immutable',
      'Vary': 'Accept-Encoding'
    },
    'html': {
      'Cache-Control': 'public, max-age=3600, must-revalidate',
      'Vary': 'Accept-Encoding'
    },
    'api': {
      'Cache-Control': 'max-age=60, stale-while-revalidate=300',
      'Vary': 'Accept, Accept-Encoding'
    },
    'private': {
      'Cache-Control': 'private, no-cache, must-revalidate'
    },
    'no-cache': {
      'Cache-Control': 'private, no-store, no-cache, must-revalidate',
      'Pragma': 'no-cache',
      'Expires': '0'
    }
  };
  
  const headers = strategies[type] || strategies['private'];
  Object.entries(headers).forEach(([key, value]) => {
    res.setHeader(key, value);
  });
  
  next();
};

// Generate ETag
const generateETag = (content) => {
  return `"${crypto.createHash('md5').update(content).digest('hex')}"`;
};

// Static assets
app.use('/static', cacheStrategy('static'), express.static('public', {
  etag: true,
  lastModified: true,
  immutable: true,
  maxAge: '1y'
}));

// HTML pages
app.get('/', cacheStrategy('html'), (req, res) => {
  const html = renderHTML();
  const etag = generateETag(html);
  
  // Check If-None-Match
  if (req.headers['if-none-match'] === etag) {
    return res.status(304).end();
  }
  
  res.setHeader('ETag', etag);
  res.setHeader('Last-Modified', new Date().toUTCString());
  res.send(html);
});

// API endpoints
app.get('/api/data', cacheStrategy('api'), (req, res) => {
  const data = fetchData();
  const etag = generateETag(JSON.stringify(data));
  
  if (req.headers['if-none-match'] === etag) {
    return res.status(304).end();
  }
  
  res.setHeader('ETag', etag);
  res.json(data);
});

// User-specific content
app.get('/dashboard', requireAuth, cacheStrategy('private'), (req, res) => {
  const userData = getUserData(req.user.id);
  const etag = generateETag(JSON.stringify(userData));
  
  if (req.headers['if-none-match'] === etag) {
    return res.status(304).end();
  }
  
  res.setHeader('ETag', etag);
  res.json(userData);
});

// Sensitive operations
app.post('/api/payment', cacheStrategy('no-cache'), (req, res) => {
  processPayment(req.body);
  res.json({ success: true });
});

app.listen(3000);
```

**Коли використовувати:** Production Node.js/Express applications з різними типами контенту

**Mobile considerations:** 
- ETag generation швидкий (md5 <5ms для 1MB)
- 304 responses економлять 95%+ bandwidth
- Stale-while-revalidate = zero perceived latency

```apache
  Header set Vary "Accept, Accept-Encoding"
</FilesMatch>

# Videos - long cache
<FilesMatch "\.(mp4|webm|ogv)$">
  Header set Cache-Control "public, max-age=2592000"
  Header set Vary "Accept-Encoding"
</FilesMatch>

# Disable caching for dynamic scripts
<FilesMatch "\.(php|cgi|pl)$">
  Header set Cache-Control "private, no-cache, no-store, must-revalidate"

</FilesMatch>

# Enable Brotli compression (if mod_brotli available)
<IfModule mod_brotli.c>
  AddOutputFilterByType BROTLI_COMPRESS text/html text/plain text/xml text/css text/javascript application/javascript application/json
</IfModule>

# Gzip compression
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css text/javascript application/javascript application/json application/xml
</IfModule>
```

**Mobile considerations:**
- Brotli compression економить 20-30% більше ніж gzip на mobile
- immutable directive підтримується всіма modern mobile browsers
- Vary: Accept-Encoding критично для mobile (різні compression capabilities)

```nginx
    }
    
    location ~* \.(woff|woff2|ttf|eot)$ {
      expires 1y;

      access_log off;
    }
    
    # HTML - short TTL
    location ~* \.(html|htm)$ {
      expires 1h;
      add_header Cache-Control "public, must-revalidate";
      add_header Vary "Accept-Encoding";
    }
    
    # API endpoints
    location /api/ {
      add_header Cache-Control "max-age=60, stale-while-revalidate=300";
      add_header Vary "Accept, Accept-Encoding";
      proxy_pass http://backend;
    }
    
    # Videos
    location ~* \.(mp4|webm|ogv)$ {
      expires 30d;
      add_header Cache-Control "public";
      add_header Vary "Accept-Encoding";
    }
    
    # No cache for sensitive endpoints
    location /admin/ {
      add_header Cache-Control "private, no-cache, no-store, must-revalidate";
      add_header Pragma "no-cache";
      add_header Expires "0";
      proxy_pass http://backend;
    }
    
    # Root location
    location / {
      try_files $uri $uri/ /index.html;
    }
  }
}
```

**Коли використовувати:** Nginx servers (VPS, cloud hosting, high-traffic sites)

**Mobile considerations:**
- HTTP/2 підтримка критична для mobile (multiplexing)
- gzip_min_length 1024 оптимально для mobile (balance compression vs CPU)
- access_log off для static assets = менше disk I/O

## ⚠️ ТИПОВІ ПОМИЛКИ ТА ЯК ЇХ УНИКНУТИ

### 1. **Помилка: Кешування HTML з `max-age=31536000`**

**Чому проблема:**
HTML часто змінюється (new content, layout updates, bug fixes). Якщо browser кешує на 1 рік, users не побачать зміни без hard refresh.

**Рішення:**
```javascript
// ❌ WRONG - HTML cached for 1 year
res.setHeader('Cache-Control', 'public, max-age=31536000');

// ✅ CORRECT - HTML cached for 1 hour with revalidation
res.setHeader('Cache-Control', 'public, max-age=3600, must-revalidate');
res.setHeader('ETag', generateETag(html));
```

**Code example правильного підходу:**
```javascript
// Best practice for HTML
app.get('/', (req, res) => {
  const html = renderHTML();
  const etag = `"${crypto.createHash('md5').update(html).digest('hex')}"`;
  
  // Check ETag first
  if (req.headers['if-none-match'] === etag) {
    return res.status(304).end(); // Cached version still valid
  }
  
  // Set headers for fresh content
  res.setHeader('Cache-Control', 'public, max-age=3600, must-revalidate');
  res.setHeader('ETag', etag);
  res.setHeader('Last-Modified', new Date().toUTCString());
  res.send(html);
});
```

### 2. **Помилка: Використання `max-age=0` замість `no-cache`**

**Чому проблема:**
`max-age=0` означає "expired immediately, але можна revalidate". `no-cache` означає "MUST revalidate before use". Subtle різниця але важлива для security.

**Рішення:**
```javascript
// ❌ WRONG - max-age=0 може бути cached
res.setHeader('Cache-Control', 'max-age=0');

// ✅ CORRECT - force revalidation
res.setHeader('Cache-Control', 'no-cache, must-revalidate');

// ✅ EVEN BETTER - completely prevent caching
res.setHeader('Cache-Control', 'private, no-store, no-cache, must-revalidate');
res.setHeader('Pragma', 'no-cache');
res.setHeader('Expires', '0');
```

### 3. **Помилка: Забування про Vary header**

**Чому проблема:**
Без `Vary: Accept-Encoding` CDN може serve gzipped content до browsers, які не підтримують gzip, або навпаки.

**Рішення:**
```apache
# ❌ WRONG - no Vary header
<FilesMatch "\.(css|js)$">
  Header set Cache-Control "public, max-age=31536000, immutable"
</FilesMatch>

# ✅ CORRECT - Vary ensures proper version served
<FilesMatch "\.(css|js)$">
  Header set Cache-Control "public, max-age=31536000, immutable"
  Header set Vary "Accept-Encoding"
</FilesMatch>
```

**Mobile specific issue:**
Mobile browsers мають різні compression capabilities. iPhone підтримує Brotli з iOS 11+, старі Android тільки gzip. Vary забезпечує правильну версію.

### 4. **Помилка: ETag з inode на distributed systems**

**Чому проблема:**
Apache default ETag включає inode (file system ID). На load-balanced servers inode різні → різні ETags → cache misses.

**Рішення:**
```apache
# ❌ WRONG - Apache default включає inode
# FileETag INode MTime Size

# ✅ CORRECT - remove inode for load-balanced setups
FileETag MTime Size

# ✅ OR - disable FileETag and generate manually
Header unset ETag
FileETag None
```

### 5. **Помилка: Кешування user-specific content з `public`**

**Чому проблема:**
`Cache-Control: public` дозволяє кешування в shared caches (CDN, proxies). User A може побачити dashboard User B!

**Рішення:**
```javascript
// ❌ WRONG - public cache for user data!
app.get('/dashboard', requireAuth, (req, res) => {
  res.setHeader('Cache-Control', 'public, max-age=3600');
  res.json(getUserData(req.user.id));
});

// ✅ CORRECT - private cache only
app.get('/dashboard', requireAuth, (req, res) => {
  res.setHeader('Cache-Control', 'private, max-age=3600, must-revalidate');
  res.setHeader('ETag', generateETag(userData));
  res.json(getUserData(req.user.id));
});
```

### Metrics to Watch:

**TTFB (Time To First Byte)**
- Target: <200ms (excellent), <500ms (good), >1000ms (needs improvement)
- Cache impact: Cached responses = 20-50ms TTFB, uncached = 200-800ms
- Mobile: 3G networks мають 200-500ms additional latency
- Measurement: Chrome DevTools Timing tab, WebPageTest

**Cache Hit Rate**
- Target: 80%+ for static assets, 50%+ for API responses
- Formula: `(cached requests / total requests) * 100`
- Optimization: Increase `max-age` values, enable stale-while-revalidate
- Mobile consideration: Lower hit rate normal (app switching, memory pressure)

**304 Response Rate**
- Target: 60%+ for HTML, 40%+ for API
- Best with: ETag + Last-Modified + appropriate max-age
- Mobile: 304 responses save bandwidth (critical on limited data plans)

# ПІДЕТАП 4.4.2: SERVICE WORKERS ДЛЯ OFFLINE

## 🔑 КЛЮЧОВІ ЗНАХІДКИ

### 1. **Service Workers - programmable network proxy для total cache control**

Service Worker - це JavaScript що працює в окремому thread, інтерцепт всі network requests і може управляти кешуванням програмно. На відміну від HTTP cache (browser controlled), Service Workers дають developer full control.

**Чому важливо для Mobile First:** Mobile users часто втрачають connection (метро, elevator, тунель). Service Workers забезпечують offline-first experience - app працює навіть без інтернету.

**Практичне застосування:** PWAs (Progressive Web Apps), offline-capable landing pages, "Install to Home Screen" functionality. Users бачать instant load навіть при 0 connectivity.

### 2. **Cache-First Strategy - найшвидша стратегія для static assets**

При Cache-First SW спочатку перевіряє cache. Якщо є - serve instantly. Якщо немає - fetch з network і cache результат. Це дає zero-latency loads для repeat visits.

**Чому важливо для Mobile First:** На mobile latency = king. Cache-First означає instant response (0-10ms vs 300-2000ms network). Battery life покращується (no radio usage).

**Практичне застосування:** CSS, JavaScript, images, fonts - все що не змінюється часто. Combines perfectly з versioned filenames (app.abc123.js).

### 3. **Network-First Strategy для fresh content**

Network-First спочатку пробує fetch з network. Якщо fail (offline, timeout) - fallback to cache. Забезпечує максимальну freshness з graceful degradation.

**Чому важливо для Mobile First:** HTML pages, API responses потребують fresh data, але повинні працювати offline. Network-First дає best of both worlds.

**Практичне застосування:** HTML documents, user profiles, news feeds, weather data - content що змінюється але має reasonable fallback.

### 4. **Stale-While-Revalidate - найкраща UX стратегія**

SWR serve з cache instantly (stale) і одночасно fetch fresh version у background. Next request отримує fresh data. Users бачать instant load + automatic updates.

**Чому важливо для Mobile First:** Zero perceived latency + always fresh. Mobile users не чекають, не помічають updates. Ідеально для modern app-like experience.

**Практичне застосування:** API endpoints, user-generated content, social feeds, analytics data - anything where slight staleness OK але users want instant response.

### 5. **Pre-caching Critical Resources на install event**

SW install event дозволяє pre-cache essential files before app навіть запущений. "App shell" (HTML/CSS/JS structure) завантажується одразу, content fills async.

**Чому важливо для Mobile First:** First-time load стає instant на всі наступні візити. Users на slow 3G networks download once, then blazing fast forever.

**Практичне застосування:** App shell pattern - cache skeleton HTML + CSS + core JS. Load page structure instantly, fetch data async. PWA "installation" pre-caches everything.

### 6. **Background Sync для offline form submissions**

Background Sync API дозволяє defer requests до connectivity restored. Users submit form offline → SW queues → auto-sends when online.

**Чому важливо для Mobile First:** Mobile users constantly lose signal. Background Sync означає "submit and forget" - no lost data, no UX friction.

**Практичне застосування:** Contact forms, e-commerce checkouts, comment submissions, analytics events - anything user-generated що must not fail.

### 7. **Workbox - production-ready SW library**

Workbox (від Google) - це набір SW utilities що implements всі caching strategies, precaching, routing, background sync. Battle-tested on billions devices.

**Чому важливо для Mobile First:** Writing SW from scratch = error-prone. Workbox handles edge cases (quota exceeded, corrupt cache, race conditions) що developers забувають.

**Практичне застосування:** Use Workbox для всіх production PWAs. Supports webpack/vite/rollup plugins для automatic generation + precache manifest.

## ⭐ BEST PRACTICES

### 1. **App Shell Pattern з Pre-caching**

**Що робити:**
```javascript
// service-worker.js
const CACHE_VERSION = 'v1.2.0';
const APP_SHELL_CACHE = `app-shell-${CACHE_VERSION}`;

// Critical resources to pre-cache
const APP_SHELL_ASSETS = [
  '/',
  '/index.html',
  '/css/app.css',
  '/js/app.js',
  '/fonts/Inter-var.woff2',
  '/img/logo.svg',
  '/offline.html' // Fallback page
];

// Install event - pre-cache app shell
self.addEventListener('install', (event) => {
  console.log('[SW] Installing...');
  
  event.waitUntil(
    caches.open(APP_SHELL_CACHE)
      .then((cache) => {
        console.log('[SW] Pre-caching app shell');
        return cache.addAll(APP_SHELL_ASSETS);
      })
      .then(() => {
        // Force activation (skip waiting)
        return self.skipWaiting();
      })
  );
});

// Activate event - cleanup old caches
self.addEventListener('activate', (event) => {
  console.log('[SW] Activating...');
  
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames
          .filter((name) => name.startsWith('app-shell-') && name !== APP_SHELL_CACHE)
          .map((name) => {
            console.log('[SW] Deleting old cache:', name);
            return caches.delete(name);
          })
      );
    }).then(() => {
      // Take control immediately
      return self.clients.claim();
    })
  );
});
```

**Чому це працює:**
- Pre-cache означає instant subsequent loads
- Version-based cache name забезпечує clean updates
- skipWaiting() + claim() = immediate activation (no page reload needed)

**Mobile First специфіка:**
- App shell typically <100KB - завантажується швидко навіть на 3G
- Offline.html fallback = graceful degradation
- Font pre-caching = no FOIT (Flash of Invisible Text)

### 2. **Tiered Caching Strategy з Route Matching**

**Що робити:**
```javascript
// service-worker.js
const STATIC_CACHE = 'static-v1';
const DYNAMIC_CACHE = 'dynamic-v1';
const IMAGE_CACHE = 'images-v1';

self.addEventListener('fetch', (event) => {
  const { request } = event;
  const url = new URL(request.url);
  
  // 1. Cache-First для static assets
  if (request.destination === 'style' || 
      request.destination === 'script' ||
      request.destination === 'font') {
    event.respondWith(
      caches.match(request).then((cached) => {
        // Return cached immediately, update in background
        const fetchPromise = fetch(request).then((response) => {
          caches.open(STATIC_CACHE).then((cache) => {
            cache.put(request, response.clone());
          });
          return response;
        });
        
        return cached || fetchPromise;
      })
    );
    return;
  }
  
  // 2. Network-First для HTML documents
  if (request.destination === 'document') {
    event.respondWith(
      fetch(request)
        .then((response) => {
          // Cache successful HTML responses
          if (response.status === 200) {
            caches.open(DYNAMIC_CACHE).then((cache) => {
              cache.put(request, response.clone());
            });
          }
          return response;
        })
        .catch(() => {
          // Fallback to cached version if offline
          return caches.match(request).then((cached) => {
            return cached || caches.match('/offline.html');
          });
        })
    );
    return;
  }
  
  // 3. Cache-First + Network fallback для images
  if (request.destination === 'image') {
    event.respondWith(
      caches.match(request).then((cached) => {
        if (cached) return cached;
        
        return fetch(request)
          .then((response) => {
            // Only cache successful image responses
            if (response.status === 200) {
              caches.open(IMAGE_CACHE).then((cache) => {
                cache.put(request, response.clone());
              });
            }
            return response;
          })
          .catch(() => {
            // Return placeholder image if failed
            return caches.match('/img/placeholder.png');
          });
      })
    );
    return;
  }
  
  // 4. Network-only для API calls (or implement SWR below)
  if (url.pathname.startsWith('/api/')) {
    event.respondWith(fetch(request));
    return;
  }
  
  // Default: try network, fallback to cache
  event.respondWith(
    fetch(request).catch(() => caches.match(request))
  );
});
```

**Чому це працює:**
- Different strategies for different content types
- Static assets = fastest (cache-first)
- HTML = freshest (network-first with offline fallback)
- Images = balanced (cache-first з network fallback)

**Mobile First специфіка:**
- request.destination API supported у всіх modern mobile browsers
- Separate cache buckets дозволяють fine-tuned quota management
- Placeholder images = no broken layouts on offline

### 3. **Stale-While-Revalidate для API Responses**

**Що робити:**
```javascript
// service-worker.js
const API_CACHE = 'api-v1';
const CACHE_EXPIRY_TIME = 5 * 60 * 1000; // 5 minutes

self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);
  
  // Stale-While-Revalidate for API endpoints
  if (url.pathname.startsWith('/api/')) {
    event.respondWith(
      caches.open(API_CACHE).then(async (cache) => {
        // Fetch from cache
        const cachedResponse = await cache.match(event.request);
        
        // Start network request (don't await)
        const fetchPromise = fetch(event.request)
          .then(async (networkResponse) => {
            // Cache fresh response with timestamp
            const responseToCache = networkResponse.clone();
            const headers = new Headers(responseToCache.headers);
            headers.append('sw-cache-time', Date.now().toString());
            
            const newResponse = new Response(responseToCache.body, {
              status: responseToCache.status,
              statusText: responseToCache.statusText,
              headers: headers
            });
            
            await cache.put(event.request, newResponse);
            return networkResponse;
          })
          .catch(() => cachedResponse); // Fallback to cache on network error
        
        // Return cached immediately if exists and not expired
        if (cachedResponse) {
          const cacheTime = cachedResponse.headers.get('sw-cache-time');
          const age = Date.now() - parseInt(cacheTime || '0');
          
          if (age < CACHE_EXPIRY_TIME) {
            // Cache still fresh, return immediately
            // Network request updates cache in background
            return cachedResponse;
          }
        }
        
        // Cache expired or doesn't exist, wait for network
        return fetchPromise;
      })
    );
  }
});
```

**Чому це працює:**
- Instant response від cache (0ms latency)
- Fresh data fetches у background
- Next request отримує updated data

### Snippet 2: IndexedDB Wrapper для SW Data Persistence

```javascript
// db.js - IndexedDB wrapper for Service Worker
class SWDatabase {
  constructor(dbName = 'sw-cache-db', version = 1) {
    this.dbName = dbName;
    this.version = version;
    this.db = null;
  }
  
  async open() {
    return new Promise((resolve, reject) => {
      const request = indexedDB.open(this.dbName, this.version);
      
      request.onerror = () => reject(request.error);
      request.onsuccess = () => {
        this.db = request.result;
        resolve(this.db);
      };
      
      request.onupgradeneeded = (event) => {
        const db = event.target.result;
        
        // Create object stores
        if (!db.objectStoreNames.contains('pending-submissions')) {
          const store = db.createObjectStore('pending-submissions', { keyPath: 'id' });
          store.createIndex('timestamp', 'timestamp', { unique: false });
        }
        
        if (!db.objectStoreNames.contains('cached-responses')) {
          const store = db.createObjectStore('cached-responses', { keyPath: 'url' });
          store.createIndex('expiry', 'expiry', { unique: false });
        }
      };
    });
  }
  
  async add(storeName, data) {
    const db = this.db || await this.open();
    return new Promise((resolve, reject) => {
      const transaction = db.transaction([storeName], 'readwrite');
      const store = transaction.objectStore(storeName);
      const request = store.add(data);
      
      request.onsuccess = () => resolve(request.result);
      request.onerror = () => reject(request.error);
    });
  }
  
  async getAll(storeName) {
    const db = this.db || await this.open();
    return new Promise((resolve, reject) => {
      const transaction = db.transaction([storeName], 'readonly');
      const store = transaction.objectStore(storeName);
      const request = store.getAll();
      
      request.onsuccess = () => resolve(request.result);
      request.onerror = () => reject(request.error);
    });
  }
  
  async delete(storeName, key) {
    const db = this.db || await this.open();
    return new Promise((resolve, reject) => {
      const transaction = db.transaction([storeName], 'readwrite');
      const store = transaction.objectStore(storeName);
      const request = store.delete(key);
      
      request.onsuccess = () => resolve();
      request.onerror = () => reject(request.error);
    });
  }
  
  async clear(storeName) {
    const db = this.db || await this.open();
    return new Promise((resolve, reject) => {
      const transaction = db.transaction([storeName], 'readwrite');
      const store = transaction.objectStore(storeName);
      const request = store.clear();
      
      request.onsuccess = () => resolve();
      request.onerror = () => reject(request.error);
    });
  }
}

// Use in Service Worker
const db = new SWDatabase();

// Queue offline form submission
self.addEventListener('fetch', (event) => {
  if (event.request.method === 'POST' && event.request.url.includes('/api/')) {
    event.respondWith(
      fetch(event.request.clone())
        .catch(async () => {
          // Network failed, queue submission
          const body = await event.request.clone().text();
          await db.add('pending-submissions', {
            id: Date.now().toString(),
            url: event.request.url,
            method: event.request.method,
            headers: Object.fromEntries(event.request.headers),
            body: body,
            timestamp: Date.now()
          });
          
          // Register background sync
          self.registration.sync.register('sync-submissions');
          
          // Return success response (queued)
          return new Response(JSON.stringify({ 
            queued: true,
            message: 'Submission saved. Will sync when online.' 
          }), {
            status: 202, // Accepted
            headers: { 'Content-Type': 'application/json' }
          });
        })
    );
  }
});
```

### 2. **Помилка: Caching opaque responses без validation**

**Чому проблема:**
CORS requests без proper headers return opaque responses (status 0). Caching їх wastes quota і може спричинити bugs.

**Рішення:**
```javascript
// ❌ WRONG - cache all responses including opaque
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.open('my-cache').then((cache) => {
      return fetch(event.request).then((response) => {
        cache.put(event.request, response.clone());
        return response;
      });
    })
  );
});

// ✅ CORRECT - validate response before caching
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.open('my-cache').then((cache) => {
      return fetch(event.request).then((response) => {
        // Only cache successful responses (200-299)
        // Don't cache opaque responses (status 0) from CORS
        if (response.status >= 200 && response.status < 300) {
          cache.put(event.request, response.clone());
        }
        return response;
      });
    })
  );
});
```

### 3. **Помилка: Not cleaning old caches on activate**

**Чому проблема:**
Кожен новий SW version створює new caches. Old caches never deleted → storage bloat → quota exceeded → SW fails.

**Рішення:**
```javascript
// ❌ WRONG - no cache cleanup
self.addEventListener('activate', (event) => {
  self.clients.claim();
});

// ✅ CORRECT - delete old caches
const CACHE_VERSION = 'v2';
const EXPECTED_CACHES = [
  `static-${CACHE_VERSION}`,
  `dynamic-${CACHE_VERSION}`,
  `images-${CACHE_VERSION}`
];

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames
          .filter((name) => !EXPECTED_CACHES.includes(name))
          .map((name) => {
            console.log('[SW] Deleting old cache:', name);
            return caches.delete(name);
          })
      );
    }).then(() => self.clients.claim())
  );
});
```

### 4. **Помилка: Forgetting to handle POST requests correctly**

**Чому проблема:**
POST requests typically не cacheable і shouldnt go through SW cache-first logic. Can cause form re-submissions або data loss.

**Рішення:**
```javascript
// ❌ WRONG - cache ALL requests including POST
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((cached) => {
      return cached || fetch(event.request);
    })
  );
});

// ✅ CORRECT - handle POST specially
self.addEventListener('fetch', (event) => {
  // Never cache POST/PUT/DELETE requests
  if (event.request.method !== 'GET') {
    event.respondWith(
      fetch(event.request).catch(() => {
        // Queue for background sync if POST failed
        if (event.request.method === 'POST') {
          return queueForSync(event.request);
        }
        throw new Error('Network request failed');
      })
    );
    return;
  }
  
  // Normal cache logic for GET requests
  event.respondWith(
    caches.match(event.request).then((cached) => {
      return cached || fetch(event.request);
    })
  );
});
```

### 5. **Помилка: Not handling Range requests (video/audio)**

**Чому проблема:**
Video/audio use Range requests (`Range: bytes=0-1023`). Caching full response doesn't work - браузер expects partial content (206 response).

**Рішення:**
```javascript
// ❌ WRONG - cache full video response for Range request
self.addEventListener('fetch', (event) => {
  if (event.request.url.endsWith('.mp4')) {
    event.respondWith(
      caches.match(event.request).then((cached) => {
        return cached || fetch(event.request);
      })
    );
  }
});

// ✅ CORRECT - handle Range requests properly
self.addEventListener('fetch', (event) => {
  if (event.request.url.endsWith('.mp4') || event.request.url.endsWith('.webm')) {
    // Check for Range header
    const rangeHeader = event.request.headers.get('range');
    
    if (rangeHeader) {
      // Let browser handle Range requests (don't cache partial responses)
      event.respondWith(fetch(event.request));
    } else {
      // Cache full video for offline playback
      event.respondWith(
        caches.match(event.request).then((cached) => {
          return cached || fetch(event.request).then((response) => {
            if (response.status === 200) {
              const cache = caches.open('videos');
              cache.then((c) => c.put(event.request, response.clone()));
            }
            return response;
          });
        })
      );
    }
  }
```

## 📈 PERFORMANCE CONSIDERATIONS

### Metrics to Watch:

**SW Installation Time**
- Target: <500ms (excellent), <2s (acceptable), >5s (too slow)
- Affected by: precache list size, network speed, device performance
- Optimization: Minimize precache assets, use lazy-loading, compress resources
- Mobile: 3G networks → longer install (3-10s normal)

**Cache Hit Rate**
- Target: 90%+ for app shell, 70%+ for images, 50%+ for API
- Measurement: Chrome DevTools Network tab → "from ServiceWorker" indicator
- Optimization: Increase cache expiry, pre-cache more assets, use SWR strategy

**Time to Interactive (TTI) with SW**
- Target: <3.5s (good), <5s (acceptable)
- SW overhead: ~100-300ms additional on first load (registration + installation)
- Benefit: Subsequent loads 2-5x faster (instant from cache)
- Mobile: First load slower, all subsequent loads dramatically faster

**Quota Usage**
- Limit: Varies by device (50MB - 500MB typical)
- Monitor: `navigator.storage.estimate()`
- Strategy: Set max cache entries, implement LRU eviction, compress stored data

```javascript
async function cacheWithCompression(request, response) {
  const cache = await caches.open('compressed-cache');
  
  // Check if response is large enough to compress
  const contentLength = response.headers.get('content-length');
  if (contentLength && parseInt(contentLength) > 1024) { // >1KB
    // Clone and compress
    const blob = await response.clone().blob();
    const compressed = await compress(blob); // Use CompressionStream API
    
    const compressedResponse = new Response(compressed, {

        'X-SW-Compressed': 'true'
      }

  return response;
}
```

**1. Detect Network Quality та Adjust Strategy**

# ПІДЕТАП 4.4.3: LOCALSTORAGE ВИКОРИСТАННЯ

## 🔑 КЛЮЧОВІ ЗНАХІДКИ

### 1. **LocalStorage - простий key-value storage для малих даних**

LocalStorage provides synchronous API для збереження string key-value pairs в браузері. Data persists indefinitely until explicitly deleted, survives browser restarts.

**Чому важливо для Mobile First:** На мобільних пристроях LocalStorage дозволяє зберігати user preferences, tokens, settings без server roundtrips. Instant access = faster perceived performance.

**Практичне застосування:** User settings (theme, language), authentication tokens (JWT), form draft autosave, simple cache для API responses. Limit ~5MB per origin.

### 2. **SessionStorage - temporary storage для single session**

SessionStorage identical API to LocalStorage але data clears when tab/browser closed. Isolated per tab - two tabs = two separate storages.

**Чому важливо для Mobile First:** Mobile users часто close apps/tabs. SessionStorage perfect для temporary state (wizard step, shopping flow, search filters) що shouldn't persist.

**Практичне застосування:** Multi-step form progress, temporary filters/sorts, one-time banners, shopping cart before checkout. No cross-tab pollution.

### 3. **IndexedDB - NoSQL database для великих structured data**

IndexedDB asynchronous, transactional database що може store objects, blobs, files. Supports indexes, cursors, transactions. Storage limit ~50% available disk space.

**Чому важливо для Mobile First:** Mobile apps need offline-capable databases. IndexedDB дозволяє store entire product catalogs, user-generated content, media files locally.

**Практичне застосування:** Offline-first PWAs, large datasets (products, articles), image/file caching, complex queries з indexes, Service Worker data persistence.

### 4. **Storage Quotas - браузери обмежують available space**

Different quotas по браузерам: Chrome (~60% free disk), Firefox (~10% total disk), Safari (~1GB mobile). When exceeded → `QuotaExceededError`.

**Чому важливо для Mobile First:** Mobile devices мають limited storage (16GB phones common). Apps must handle quota gracefully - compress data, implement LRU eviction, request persistent storage.

**Практичне застосування:** Use `navigator.storage.estimate()` to check usage, implement data compression, delete old entries, request `navigator.storage.persist()` для critical data.

### 5. **Synchronous vs Asynchronous Performance**

LocalStorage synchronous = blocks main thread during read/write. На slow devices = jank/lag. IndexedDB async = non-blocking, better performance.

**Чому важливо для Mobile First:** Mobile CPUs slower ніж desktop. Synchronous LocalStorage operations можуть block UI до 50-200ms. IndexedDB non-blocking = smooth 60fps animations.

**Практичне застосування:** Use LocalStorage тільки для small data (<1KB). Use IndexedDB для anything larger. Never localStorage operations in hot loops або animations.

### 6. **Security Considerations - client-side storage не secure**

LocalStorage/SessionStorage/IndexedDB accessible via JavaScript = vulnerable to XSS attacks. Sensitive data (passwords, credit cards) should NEVER be stored client-side.

**Чому важливо для Mobile First:** Mobile browsers share data across all apps. Malicious app може read storage від інших sites (if XSS present). Defense in depth critical.

**Практичне застосування:** Never store passwords, credit cards, SSN, medical data. Store only non-sensitive data. Use httpOnly cookies для auth tokens. Encrypt sensitive preferences if must store locally.

### 7. **Storage API для unified quota management**

`navigator.storage` API provides unified interface: `estimate()` (check usage), `persist()` (request persistent storage), `persisted()` (check if persistent).

**Чому важливо для Mobile First:** Mobile OS агресивно evict data when storage low (особливо Safari iOS). Persistent storage prevents eviction для critical PWA data.

**Практичне застосування:** Request persistent storage on PWA install, monitor quota with `estimate()`, show warnings before quota exceeded, implement graceful degradation.

## ⭐ BEST PRACTICES

### 1. **User Preferences - LocalStorage з Type Safety**

**Що робити:**
```javascript
// preferences.js - Type-safe LocalStorage wrapper
class PreferencesManager {
  constructor(namespace = 'app-prefs') {
    this.namespace = namespace;
    this.defaults = {
      theme: 'light',
      language: 'en',
      fontSize: 'medium',
      reducedMotion: false,
      notifications: true
    };
  }
  
  // Get preference with type validation
  get(key) {
    try {
      const value = localStorage.getItem(`${this.namespace}:${key}`);
      if (value === null) return this.defaults[key];
      
      // Parse and validate type
      const parsed = JSON.parse(value);
      const defaultType = typeof this.defaults[key];
      
      if (typeof parsed !== defaultType) {
        console.warn(`Type mismatch for ${key}, using default`);
        return this.defaults[key];
      }
      
      return parsed;
    } catch (error) {
      console.error(`Error reading preference ${key}:`, error);
      return this.defaults[key];
    }
  }
  
  // Set preference with validation
  set(key, value) {
    try {
      // Validate against defaults
      if (!(key in this.defaults)) {
        throw new Error(`Unknown preference key: ${key}`);
      }
      
      const defaultType = typeof this.defaults[key];
      if (typeof value !== defaultType) {
        throw new Error(`Type mismatch: expected ${defaultType}, got ${typeof value}`);
      }
      
      localStorage.setItem(
        `${this.namespace}:${key}`,
        JSON.stringify(value)
      );
      
      // Dispatch custom event for reactive updates
      window.dispatchEvent(new CustomEvent('preferenceChanged', {
        detail: { key, value }
      }));
      
      return true;
    } catch (error) {
      if (error.name === 'QuotaExceededError') {
        console.error('Storage quota exceeded');
        this.cleanup(); // Auto-cleanup
      } else {
        console.error(`Error saving preference ${key}:`, error);
      }
      return false;
    }
  }
  
  // Get all preferences
  getAll() {
    const prefs = {};
    Object.keys(this.defaults).forEach((key) => {
      prefs[key] = this.get(key);
    });
    return prefs;
  }
  
  // Reset to defaults
  reset() {
    Object.keys(this.defaults).forEach((key) => {
      localStorage.removeItem(`${this.namespace}:${key}`);
    });
  }
  
  // Cleanup old/invalid entries
  cleanup() {
    const keysToRemove = [];
    for (let i = 0; i < localStorage.length; i++) {
      const key = localStorage.key(i);
      if (key.startsWith(this.namespace) && 
          !Object.keys(this.defaults).some(k => key.endsWith(k))) {
        keysToRemove.push(key);
      }
    }
    keysToRemove.forEach(key => localStorage.removeItem(key));
    console.log(`Cleaned up ${keysToRemove.length} old preferences`);
  }
}
```

```javascript
// cache-manager.js - Smart LocalStorage cache
class LocalStorageCache {
  constructor(namespace = 'api-cache', maxSize = 4 * 1024 * 1024) { // 4MB default
    this.namespace = namespace;
    this.maxSize = maxSize;
  }
  
  // Generate cache key
  key(url, params = {}) {
    const paramsStr = JSON.stringify(params);
    return `${this.namespace}:${url}:${btoa(paramsStr)}`;
  }
  
  // Set cached response with TTL
  async set(url, data, ttlSeconds = 300) {
    const key = this.key(url);
    const entry = {
      data: data,
      timestamp: Date.now(),
      ttl: ttlSeconds * 1000,
      size: JSON.stringify(data).length
    };
    
    try {
      // Check if would exceed max size
      const currentSize = this.getTotalSize();
      if (currentSize + entry.size > this.maxSize) {
        this.evictOldest();
      }
      
      // Compress large responses
      if (entry.size > 10 * 1024) { // >10KB
        entry.data = await this.compress(JSON.stringify(data));
        entry.compressed = true;
      }
      
      localStorage.setItem(key, JSON.stringify(entry));
      return true;
    } catch (error) {
      if (error.name === 'QuotaExceededError') {
        console.warn('Quota exceeded, evicting cache entries');
        this.evictOldest(3); // Evict 3 oldest
        try {
          localStorage.setItem(key, JSON.stringify(entry));
          return true;
        } catch (e) {
          console.error('Still quota exceeded after eviction');
          return false;
        }
      }
      console.error('Cache set error:', error);
      return false;
    }
  }
  
  // Get cached response if not expired
  async get(url, params = {}) {
    const key = this.key(url, params);
    
    try {
      const item = localStorage.getItem(key);
      if (!item) return null;
      
      const entry = JSON.parse(item);
      const age = Date.now() - entry.timestamp;
      
      // Check if expired
      if (age > entry.ttl) {
        localStorage.removeItem(key);
        return null;
      }
      
      // Decompress if needed
      if (entry.compressed) {
        const decompressed = await this.decompress(entry.data);
        return JSON.parse(decompressed);
      }
      
      return entry.data;
    } catch (error) {
      console.error('Cache get error:', error);
      localStorage.removeItem(key); // Remove corrupted entry
      return null;
    }
  }
  
  // Remove specific cache entry
  remove(url, params = {}) {
    const key = this.key(url, params);
    localStorage.removeItem(key);
  }
  
  // Clear all cache entries
  clear() {
    const keysToRemove = [];
    for (let i = 0; i < localStorage.length; i++) {
      const key = localStorage.key(i);
      if (key.startsWith(this.namespace)) {
        keysToRemove.push(key);
      }
    }
    keysToRemove.forEach(key => localStorage.removeItem(key));
    console.log(`Cleared ${keysToRemove.length} cache entries`);
  }
  
  // Get total cache size
  getTotalSize() {
    let total = 0;
    for (let i = 0; i < localStorage.length; i++) {
      const key = localStorage.key(i);
      if (key.startsWith(this.namespace)) {
        const item = localStorage.getItem(key);
        total += item.length;
      }
    }
    return total;
  }
  
  // Evict oldest entries
  evictOldest(count = 1) {
    const entries = [];
    for (let i = 0; i < localStorage.length; i++) {
      const key = localStorage.key(i);
      if (key.startsWith(this.namespace)) {
        try {
          const item = localStorage.getItem(key);
          const entry = JSON.parse(item);
          entries.push({ key, timestamp: entry.timestamp });
        } catch (e) {
          // Remove corrupted entry
          localStorage.removeItem(key);
        }
      }
    }
    
    // Sort by timestamp (oldest first)
    entries.sort((a, b) => a.timestamp - b.timestamp);
    
    // Remove oldest
    const toRemove = entries.slice(0, count);
    toRemove.forEach(entry => localStorage.removeItem(entry.key));
    
    console.log(`Evicted ${toRemove.length} oldest cache entries`);
  }
  
  // Compress string (simplified - use CompressionStream in production)
  async compress(str) {
    // In production, use CompressionStream API or pako library
    // Here: simple base64 encoding as placeholder
    return btoa(str);
  }
  
  // Decompress string
  async decompress(str) {
    return atob(str);
  }
}

// Usage with Fetch
const cache = new LocalStorageCache('api-cache', 4 * 1024 * 1024);

async function fetchWithCache(url, options = {}) {
  const { ttl = 300, bypassCache = false } = options;
  
  // Check cache first (unless bypass)
  if (!bypassCache) {
    const cached = await cache.get(url);
    if (cached) {
      console.log('✓ Cache hit:', url);
      return cached;
    }
  }
  
  // Fetch from network
  console.log('⚡ Cache miss, fetching:', url);
  const response = await fetch(url);
  
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}: ${response.statusText}`);
  }
  
  const data = await response.json();
  
  // Cache response
  await cache.set(url, data, ttl);
  
  return data;
}
```

```javascript
// form-autosave.js - Auto-save form drafts
class FormAutosave {
  constructor(formId, options = {}) {
    this.form = document.getElementById(formId);
    if (!this.form) throw new Error(`Form ${formId} not found`);
    
    this.options = {
      debounceMs: 1000,
      storageKey: `form-draft-${formId}`,
      excludeFields: ['password', 'creditcard'],
      onSave: null,
      onRestore: null,
      ...options
    };
    
    this.debounceTimer = null;
    this.init();
  }
  
  init() {
    // Restore draft on load
    this.restoreDraft();
    
    // Auto-save on input change
    this.form.addEventListener('input', (e) => {
      // Skip excluded fields
      if (this.options.excludeFields.includes(e.target.name)) {
        return;
      }
      
      this.debouncedSave();
    });
    
    // Clear draft on successful submit
    this.form.addEventListener('submit', () => {
      this.clearDraft();
    });
    
    // Warn before leaving with unsaved draft
    window.addEventListener('beforeunload', (e) => {
      const draft = this.getDraft();
      if (draft && Object.keys(draft).length > 0) {
        e.preventDefault();
        e.returnValue = 'You have unsaved changes. Are you sure you want to leave?';
        return e.returnValue;
      }
    });
  }
  
  debouncedSave() {
    clearTimeout(this.debounceTimer);
    this.debounceTimer = setTimeout(() => {
      this.saveDraft();
    }, this.options.debounceMs);
  }
  
  saveDraft() {
    const formData = new FormData(this.form);
    const draft = {};
    
    for (const [name, value] of formData.entries()) {
      // Skip excluded fields
      if (this.options.excludeFields.includes(name)) {
        continue;
      }
      
      // Handle multiple values (checkboxes/multi-select)
      if (draft[name]) {
        if (Array.isArray(draft[name])) {
          draft[name].push(value);
        } else {
          draft[name] = [draft[name], value];
        }
      } else {
        draft[name] = value;
      }
    }
    
    // Add metadata
    const draftWithMeta = {
      data: draft,
      timestamp: Date.now(),
      url: window.location.href
    };
    
    try {
      localStorage.setItem(
        this.options.storageKey,
        JSON.stringify(draftWithMeta)
      );
      
      console.log('✓ Draft saved:', Object.keys(draft).length, 'fields');
      
      // Show save indicator
      this.showSaveIndicator();
      
      // Callback
      if (this.options.onSave) {
        this.options.onSave(draft);
      }
    } catch (error) {
      console.error('Failed to save draft:', error);
      if (error.name === 'QuotaExceededError') {
        this.showQuotaError();
      }
    }
  }
  
  restoreDraft() {
    try {
      const stored = localStorage.getItem(this.options.storageKey);
      if (!stored) return;
      
      const draftWithMeta = JSON.parse(stored);
      const draft = draftWithMeta.data;
      
      // Check if draft is from same URL
      if (draftWithMeta.url !== window.location.href) {
        console.log('Draft URL mismatch, not restoring');
        return;
      }
      
      // Check draft age (don't restore drafts older than 7 days)
      const age = Date.now() - draftWithMeta.timestamp;
      const maxAge = 7 * 24 * 60 * 60 * 1000; // 7 days
      if (age > maxAge) {
        console.log('Draft too old, clearing');
        this.clearDraft();
        return;
      }
      
      // Show restore prompt
      this.showRestorePrompt(draft, () => {
        // Restore form values
        Object.entries(draft).forEach(([name, value]) => {
          const field = this.form.elements[name];
          if (!field) return;
          
          if (field.type === 'checkbox') {
            field.checked = value === 'on' || value === true;
          } else if (field.type === 'radio') {
            const radio = this.form.querySelector(`[name="${name}"][value="${value}"]`);
            if (radio) radio.checked = true;
          } else {
            field.value = value;
          }
        });
        
        console.log('✓ Draft restored:', Object.keys(draft).length, 'fields');
        
        // Callback
        if (this.options.onRestore) {
          this.options.onRestore(draft);
        }
      });
    } catch (error) {
      console.error('Failed to restore draft:', error);
      // Clear corrupted draft
      this.clearDraft();
    }
  }
  
  getDraft() {
    try {
      const stored = localStorage.getItem(this.options.storageKey);
      return stored ? JSON.parse(stored).data : null;
    } catch (error) {
      return null;
    }
  }
  
  clearDraft() {
    localStorage.removeItem(this.options.storageKey);
    console.log('✓ Draft cleared');
  }
  
  showSaveIndicator() {
    // Simple indicator (customize as needed)
    const indicator = document.getElementById('save-indicator');
    if (indicator) {
      indicator.textContent = '✓ Draft saved';
      indicator.classList.add('visible');
      setTimeout(() => {
        indicator.classList.remove('visible');
      }, 2000);
    }
  }
  
  showRestorePrompt(draft, onRestore) {
    const fieldCount = Object.keys(draft).length;
    const message = `Found saved draft with ${fieldCount} fields. Restore?`;
    
    if (confirm(message)) {
      onRestore();
    } else {
      this.clearDraft();
    }
  }
  
  showQuotaError() {
    alert('Unable to save draft: storage quota exceeded. Please clear some browser data.');
  }
}

// Usage
const autosave = new FormAutosave('contact-form', {
  debounceMs: 1500, // Save after 1.5s of inactivity
  excludeFields: ['password', 'creditcard'],
  onSave: (draft) => {
    console.log('Draft saved:', draft);
  },
  onRestore: (draft) => {
    console.log('Draft restored:', draft);
  }
});
```
