# Testing Strategies для Mobile First HTML Single Page розробки

## Executive Summary

**INP замінив FID** як Core Web Vital 12 березня 2024 року — це найзначніша зміна в тестуванні продуктивності. **Google Optimize припинив роботу** 30 вересня 2023 року, що змусило розробників мігрувати на VWO, Optimizely або Convert. Сучасне тестування Mobile First SPA вимагає комплексного підходу: автоматизоване тестування в CI/CD (Playwright + Lighthouse CI), реальні пристрої для валідації (BrowserStack/LambdaTest), та RUM моніторинг у продакшені (Datadog, SpeedCurve).

## Ключові знахідки

**1. Playwright домінує в cross-browser тестуванні** (65К+ зірок на GitHub)
- Найкращий вибір для Mobile First SPA тестування в 2024-2025
- Підтримка Chromium, Firefox, WebKit з вбудованою емуляцією 100+ пристроїв
- Auto-wait механізми ідеально підходять для асинхронних SPA

**2. Оптимальна стратегія: 70% емулятори + 30% реальні пристрої**
- Емулятори для швидкої ітерації в розробці
- Реальні пристрої для фінальної валідації
- Хмарні ферми (BrowserStack/LambdaTest) для повного покриття
- Економія: $5K/рік vs $50-200K для власної лабораторії

**3. Критичні розміри екранів для тестування (2024)**
- **360×800px** — 11.01% (найпопулярніший, бюджетні смартфони)
- **390×844px** — 7.92% (iPhone 13, 14, 15)
- **414×896px** — 5.55% (iPhone 11, XR)
- **393×873px** — 5.26% (сучасні Android)
- **412×915px** — 5.00% (флагманські Android)

**4. Нові Core Web Vitals метрики (2024)**
- **INP** (Interaction to Next Paint) замінив FID: Good ≤200ms
- **LCP** (Largest Contentful Paint): Good ≤2.5s
- **CLS** (Cumulative Layout Shift): Good ≤0.1
- Chrome DevTools тепер показує метрики безпосередньо (Chrome 129+)

**5. Performance бюджети для Mobile First SPA**
- JavaScript (gzipped): **<170KB**
- CSS (gzipped): **<50KB**
- Total page weight: **<500KB**
- TTI на Slow 3G: **<5s**
- INP: **<200ms**

**6. WCAG 2.2 нові критерії (жовтень 2024)**
- **2.5.8 Target Size Minimum (AA)**: 24×24px мінімум (рекомендовано 48×48px)
- **2.4.11 Focus Appearance**: Видимі індикатори фокусу обов'язкові
- **2.5.7 Dragging Movements**: Альтернативи жестам drag-and-drop

**7. Microsoft Clarity — безкоштовна альтернатива Hotjar**
- 100% безкоштовно назавжди
- Heatmaps, session recordings, AI Copilot
- Mobile SDK для iOS, Android, React Native, Flutter
- 13 місяців зберігання даних

**8. axe-core виявляє 57% проблем доступності автоматично**
- Нуль false positives
- Інтеграція з Jest, Cypress, Playwright, Selenium
- Обов'язковий інструмент для CI/CD

**9. Firebase A/B Testing — єдина безкоштовна альтернатива**
- До 300 експериментів, 24 одночасно, 8 варіантів
- Google Optimize більше не існує (закритий вересень 2023)
- Для складніших потреб: VWO, Optimizely, Convert

**10. Safari iOS має специфічні quirks**
- Date pickers працюють інакше
- Video autoplay має обмеження
- CSS fixes потрібні для -webkit-appearance
- Обов'язкове тестування на реальних iPhone

## Best Practices з прикладами

### 1. Mobile-First CSS з Progressive Enhancement

```css
/* Базові мобільні стилі (без media query) */
body {
  font-size: 16px; /* Мінімум для мобільних */
  padding: 10px;
  line-height: 1.5;
}

.button {
  min-width: 48px;  /* Apple HIG: 44px, Material: 48px */
  min-height: 48px;
  padding: 12px 16px;
  font-size: 16px;
}

/* Покращення для планшетів */
@media (min-width: 768px) {
  body {
    font-size: 18px;
    padding: 20px;
  }
}

/* Покращення для десктопів */
@media (min-width: 1024px) {
  body {
    font-size: 20px;
    max-width: 1200px;
    margin: 0 auto;
  }
}

/* Prevent horizontal scrolling */
html, body {
  overflow-x: hidden;
  max-width: 100%;
}

* {
  box-sizing: border-box;
}
```

### 4. Доступний Focus Trap для модальних вікон

```javascript
const modal = document.querySelector('[role="dialog"]');
const focusableElements = modal.querySelectorAll(
  'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
);
const firstElement = focusableElements[0];
const lastElement = focusableElements[focusableElements.length - 1];

// Відкриття модалки
function openModal() {
  modal.hidden = false;
  modal.setAttribute('aria-hidden', 'false');
  firstElement.focus();
  document.body.style.overflow = 'hidden';
}

// Trap focus
modal.addEventListener('keydown', (e) => {
  if (e.key === 'Tab') {
    if (e.shiftKey && document.activeElement === firstElement) {
      e.preventDefault();
      lastElement.focus();
    } else if (!e.shiftKey && document.activeElement === lastElement) {
      e.preventDefault();
      firstElement.focus();
    }
  }
  
  if (e.key === 'Escape') {
    closeModal();
  }
});
```

### Mobile SPA Test Suite

```typescript
import { test, expect } from '@playwright/test';

test.describe('Mobile SPA Navigation', () => {
  test('navigates without page reload', async ({ page }) => {
    await page.goto('/');
    await page.click('[data-testid="nav-products"]');
    await expect(page).toHaveURL(/.*products/);
    await expect(page.locator('[data-testid="app-header"]')).toBeVisible();
  });

  test('handles touch interactions', async ({ page }) => {
    await page.goto('/');
    await page.touchscreen.swipe({
      start: { x: 300, y: 300 },
      end: { x: 100, y: 300 },
    });
    await expect(page.locator('[data-testid="next-card"]')).toBeVisible();
  });

  test('loads fast on 3G', async ({ page, context }) => {
    await context.route('**/*', route => {
      setTimeout(() => route.continue(), 500);
    });
    
    const startTime = Date.now();
    await page.goto('/');
    const loadTime = Date.now() - startTime;
    expect(loadTime).toBeLessThan(5000);
  });
});
```

```yaml
name: Mobile Testing Pipeline

  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

    runs-on: ubuntu-latest

      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4

      - run: npm ci
      - run: npx playwright install --with-deps
      - run: npx playwright test --project="${{ matrix.project }}"

        if: always()
        with:
          name: playwright-report-${{ matrix.project }}
          path: playwright-report/

    runs-on: ubuntu-latest

      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm install -g @lhci/cli@0.15.x
      - run: npm run build
      - run: lhci autorun
```

## Типові помилки та як їх уникнути

### 1. Тестування тільки на емуляторах
**Проблема**: Пропускається 20-30% багів, що виявляються тільки на реальних пристроях.
**Рішення**: Гібридна стратегія 70/30 (емулятори/реальні пристрої).

### 2. Desktop-First підхід
**Проблема**: 60%+ трафіку з мобільних, складніше оптимізувати вниз.
**Рішення**: Mobile-First CSS з progressive enhancement.

### 3. Ігнорування мережевих умов
**Проблема**: 50%+ користувачів на 3G/4G.
**Рішення**: Тестування з Slow 3G throttling (400 Kbps, 2000ms RTT).

### 4. Маленькі touch targets
**Проблема**: Складно натиснути, порушення WCAG 2.5.8.
**Рішення**: Мінімум 48×48px для всіх інтерактивних елементів.

### 5. Тестування тільки portrait орієнтації
**Проблема**: 20-30% користувачів використовують landscape.
**Рішення**: Тестування обох орієнтацій для всіх критичних flow.

### 6. Відсутність performance budgets
**Проблема**: Поступове погіршення продуктивності.
**Рішення**: Lighthouse CI з суворими assertions в CI/CD.

### 7. Тільки автоматизоване тестування
**Проблема**: Автоматизація виявляє тільки ~60% проблем.
**Рішення**: 70% automation + 20% manual + 10% user testing.

### 8. Ігнорування accessibility
**Проблема**: Юридичні ризики, 15% користувачів виключені.
**Рішення**: axe-core в CI/CD + мануальне тестування з screen readers.

### 9. Занадто багато варіантів в A/B тестах
**Проблема**: Потрібно більше трафіку, довше досягається significance.
**Рішення**: Максимум 2-3 варіанти, мінімум 2 тижні, 95% confidence.

### 10. Не тестування Safari iOS
**Проблема**: 30%+ користувачів на iOS, унікальні баги Safari.
**Рішення**: Обов'язкове тестування на реальних iPhone пристроях.

## Висновки

Mobile First HTML Single Page testing в 2024-2025 вимагає **комплексного підходу** з трьома ключовими компонентами:

### 1. Автоматизоване Lab Testing (Foundation)
- **Playwright** для E2E тестування на емуляторах
- **Lighthouse CI** для performance і accessibility в CI/CD
- **axe-core** для automated accessibility testing
- **GitHub Actions** для continuous testing
- **Покриття**: 70-80% всіх issues

### 2. Real Device Validation (Critical)
- **BrowserStack/LambdaTest** для тестування на реальних пристроях
- Фокус на **5 найпопулярніших розмірів екранів**
- Обов'язкове тестування **Safari iOS** та **Chrome Android**
- Manual testing з **VoiceOver** та **TalkBack**
- **Покриття**: додаткові 15-20% issues

### 3. Production Monitoring (Continuous)
- **Microsoft Clarity** (безкоштовно) або **SpeedCurve/Datadog** (paid)
- Real User Monitoring для **Core Web Vitals**
- **A/B testing** для conversion optimization
- **Heatmaps** та **session recordings** для UX insights
- **Покриття**: real-world performance data

### Ключові метрики успіху:
✅ **INP <200ms** (новий Core Web Vital 2024)
✅ **LCP <2.5s** на Slow 3G
✅ **JavaScript bundle <170KB** gzipped
✅ **Touch targets ≥48×48px**
✅ **WCAG 2.2 Level AA** compliance
✅ **95%+ test automation** в CI/CD
✅ **<5 minutes** CI/CD execution time

### ROI тестування:
- **300-500% ROI** через зменшення production bugs
- **95% bugs** виявляються до production
- **27% conversion increase** при покращенні швидкості на 1 секунду
- **Економія $50-200K/рік** vs власна device lab

**Найважливіше**: Тестування — це **не разова активність**, а **continuous process**. Почніть з безкоштовних інструментів (Playwright, Lighthouse, Clarity, axe-core), впроваджуйте поступово, та масштабуйте на базі metrics і business needs.
