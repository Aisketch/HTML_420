## HTML Validation: Забезпечення стандартів та доступності

**Сучасний підхід до HTML валідації поєднує три рівні:** швидку перевірку в редакторі через HTMLHint, комплексну валідацію через Nu Html Checker, та офіційну W3C перевірку в CI/CD. Критична відмінність для SPA: валідувати потрібно **зібраний production HTML**, а не вихідний код, оскільки React/Vue/Angular генерують розмітку динамічно.

### Ключові інструменти та конфігурації

HTMLHint залишається найшвидшим рішенням для локальної розробки з підтримкою всіх сучасних HTML5 стандартів. Конфігурація для Mobile First SPA має враховувати семантичну розмітку, accessibility атрибути та обов'язкові meta теги для мобільних пристроїв.

**Nu Html Checker інтеграція для CI/CD:**

```javascript
// validate-html.js
const { exec } = require('child_process');
const path = require('path');

function validateHTML(filePath) {
  const vnuPath = path.join(__dirname, 'node_modules', 'vnu-jar', 'build', 'dist', 'vnu.jar');
  
  return new Promise((resolve, reject) => {
    exec(`java -jar ${vnuPath} --format json ${filePath}`, (error, stdout, stderr) => {
      if (stderr) {
        const result = JSON.parse(stderr);
        console.log(`Знайдено ${result.messages.length} проблем валідації`);
        result.messages.forEach(msg => {
          console.log(`${msg.type}: ${msg.message} (рядок ${msg.lastLine})`);
        });
        resolve(result);
      } else {
        resolve({ messages: [] });
      }
    });
  });
}

validateHTML('./dist/index.html');
```

### Мобільно-специфічна валідація

Критичні перевірки для Mobile First включають обов'язкову наявність viewport meta тегу, правильні touch-icon посилання, та manifest.json для PWA функціональності.

**Автоматизована перевірка мобільних вимог:**

```javascript
const mobileValidationChecks = {
  hasViewport: html => /<meta\s+name=["']viewport["']/.test(html),
  hasCharset: html => /<meta\s+charset=["']UTF-8["']/i.test(html),
  hasLang: html => /<html[^>]+lang=["'][a-z]{2}["']/i.test(html),
  hasTitle: html => /<title>.+<\/title>/.test(html),
  hasManifest: html => /<link[^>]+rel=["']manifest["']/.test(html),
  hasTouchIcon: html => /<link[^>]+rel=["']apple-touch-icon["']/.test(html)
};

function validateMobilePage(html) {
  const results = {};
  for (const [check, validator] of Object.entries(mobileValidationChecks)) {
    results[check] = validator(html);
  }
  return results;
}
```

### Типові помилки та рішення

**Проблема 1: Порожні root елементи** у React/Vue додатках. Валідатори бачать порожній `<div id="app"></div>` як проблему. **Рішення:** додавати fallback контент або `<noscript>` повідомлення.

**Проблема 2: Дубльовані ID** при рендерингу компонентів. **Рішення:** використовувати унікальні ID через props або data-атрибути замість статичних ID.

**Проблема 3: Невалідні ARIA атрибути**. **Рішення:** використовувати семантичні HTML5 елементи (`<button>`, `<nav>`) замість `<div role="button">`.

### PurgeCSS для видалення невикористаного CSS

У SPA критично важливо видаляти невикористаний CSS, який може становити 60-90% бандлу. PurgeCSS аналізує контент файли та видаляє неактивні селектори.

**PostCSS конфігурація з PurgeCSS:**

```javascript
// postcss.config.js
module.exports = {
  plugins: [
    require('stylelint')({
      config: { extends: 'stylelint-config-standard' }
    }),
    require('autoprefixer'),
    require('@fullhuman/postcss-purgecss')({
      content: ['./src/**/*.html', './src/**/*.js'],
      defaultExtractor: content => content.match(/[\w-/:]+(?<!:)/g) || [],
      safelist: {
        standard: [/^is-/, /^has-/],
        deep: [/modal/, /dropdown/],
        greedy: [/tooltip$/]
      },
      variables: true,
      keyframes: true
    }),
    require('cssnano')({ preset: 'default' })
  ]
};
```

### Типові CSS проблеми в SPA

**Проблема: CSS bloat** - SPA завантажують весь CSS бандл на старті. **Рішення:** code splitting CSS по маршрутах, PurgeCSS у production, критичний CSS inline.

**Проблема: Render-blocking CSS** блокує LCP. **Рішення:** критичний CSS inline, асинхронне завантаження повного бандлу через `<link rel="preload">`.

**Проблема: CSS animations спричиняють layout shifts**. **Рішення:** використовувати тільки `transform` та `opacity` для анімацій (GPU-accelerated).

## Link Checking: Забезпечення цілісності навігації

**Критичний виклик для SPA:** традиційні link checkers НЕ працюють з JavaScript-рендереними додатками. Рішення - перевіряти зібраний production HTML або використовувати headless браузери.

### Linkinator - найкраще рішення для SPA

Linkinator підтримує рекурсивний crawling, працює з localhost та production, має event-driven API і досягає швидкості 100+ URL/секунду.

**Комплексний link checker скрипт:**

```javascript
// check-links.mjs
import { LinkChecker } from 'linkinator';
import chalk from 'chalk';

const BASE_URL = 'http://localhost:3000';

const LOGGER_MAP = {
  OK: chalk.green('.'),
  BROKEN: chalk.red('!'),
  SKIPPED: chalk.yellow('?')
};

const checker = new LinkChecker();
let brokenLinks = [];

checker.on('link', (link) => {
  process.stdout.write(LOGGER_MAP[link.state]);
  if (link.state === 'BROKEN') {
    brokenLinks.push(link);
  }
});

const result = await checker.check({
  path: BASE_URL,
  recurse: true,
  timeout: 5000,
  linksToSkip: [
    'https://twitter.com',
    'https://linkedin.com'
  ]
});

console.log('\n\n=== Результати перевірки посилань ===');
console.log(`Всього перевірено: ${result.links.length}`);
console.log(`Битих: ${brokenLinks.length}`);

if (brokenLinks.length > 0) {
  console.log('\n❌ Биті посилання:');
  brokenLinks.forEach(link => {
    console.log(`\n${link.url}`);
    console.log(`  Статус: ${link.status}`);
    console.log(`  Джерело: ${link.parent}`);
  });
  process.exit(1);
}

console.log('\n✅ Всі посилання валідні!');
```

## Image Optimization Verification: Сучасні формати та продуктивність

**AVIF досяг universal browser support у 2024 році**, забезпечуючи 20% кращу компресію ніж WebP. Критичні метрики: LCP \u003c2.5s, CLS \u003c0.1, та proper lazy loading для below-fold зображень.

### Формати та browser support

**Ієрархія форматів у 2024-2025:**
- AVIF (quality 50) = WebP/JPEG (quality 90) за Adobe testing
- WebP забезпечує 27% reduction over JPEG
- AVIF підтримується в 100% major browsers з січня 2024

**Правильна HTML імплементація:**

```html

  <source srcset="/images/hero.avif" type="image/avif" />
  <source srcset="/images/hero.webp" type="image/webp" />
  <img src="/images/hero.jpg" alt="Hero" width="1200" height="600" />
</picture>
```

### Lazy loading верифікація

**Критичне правило:** НІКОЛИ не lazy load LCP images (hero images above fold).

```html
<!-- Proper implementation -->
<img src="image.jpg" loading="lazy" alt="Description" width="800" height="600" />

<!-- ⚠️ NEVER lazy load LCP images -->
<img src="hero.jpg" loading="eager" fetchpriority="high" alt="Hero" />
```

**Intersection Observer для advanced control:**

```javascript
const lazyImageObserver = new IntersectionObserver((entries, observer) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;
      img.onload = () => img.classList.add('loaded');
      img.onerror = () => {
        img.src = 'fallback.jpg';
        console.error('Failed to load:', img.dataset.src);
      };
      observer.unobserve(img);
    }
  });
}, {
  rootMargin: '50px',
  threshold: 0.1
});

document.querySelectorAll('img[data-src]').forEach(img => {
  lazyImageObserver.observe(img);
});
```

### LCP оптимізація

**LCP breakdown formula:**
```
LCP = TTFB + Resource Load Delay + Resource Load Duration + Element Render Delay

Optimal:
- TTFB: <800ms (40% бюджету)
- Resource Load Delay: ~0ms (використати preload)
- Resource Load Duration: мінімізувати через compression
- Element Render Delay: ~0ms (уникати render-blocking)
```

**Measuring LCP з web-vitals:**

```javascript
import { onLCP } from 'web-vitals';

onLCP(metric => {
  console.log('LCP:', metric.value);
  console.log('Element:', metric.entries[metric.entries.length - 1].element);
  
  gtag('event', 'LCP', {
    value: Math.round(metric.value),
    metric_id: metric.id
  });
});
```

### Автоматизована перевірка форматів

```javascript
// check-image-formats.js
const fs = require('fs');
const path = require('path');

function checkImageFormats(dir) {
  const images = [];
  const legacyFormats = ['.jpg', '.jpeg', '.png'];
  
  function scanDirectory(directory) {
    fs.readdirSync(directory).forEach(file => {
      const fullPath = path.join(directory, file);
      const stat = fs.statSync(fullPath);
      
      if (stat.isDirectory()) {
        scanDirectory(fullPath);
      } else {
        const ext = path.extname(file).toLowerCase();
        if (['.jpg', '.jpeg', '.png', '.webp', '.avif'].includes(ext)) {
          images.push({ 
            path: fullPath, 
            format: ext, 
            isLegacy: legacyFormats.includes(ext) 
          });
        }
      }
    });
  }
  
  scanDirectory(dir);
  
  const warnings = [];
  images.filter(img => img.isLegacy).forEach(img => {
    const baseName = img.path.replace(/\.(jpe?g|png)$/i, '');
    const hasWebP = images.some(i => i.path === `${baseName}.webp`);
    const hasAVIF = images.some(i => i.path === `${baseName}.avif`);
    
    if (!hasWebP && !hasAVIF) {
      warnings.push(`⚠️  ${img.path} відсутні WebP/AVIF варіанти`);
    }
  });
  
  if (warnings.length > 0) {
    warnings.forEach(w => console.log(w));
    process.exit(1);
  }
}

checkImageFormats('./public/images');
```

### Автоматизований detector placeholder тексту

```javascript
// placeholder-detector.js
const fs = require('fs').promises;
const path = require('path');

const PLACEHOLDER_PATTERNS = [
  /lorem\s+ipsum/gi,
  /dolor\s+sit\s+amet/gi,
  /\[placeholder\]/gi,
  /\[TODO:?\s*.*?\]/gi,
  /\[FIXME:?\s*.*?\]/gi,
  /\bTBD\b/gi,
  /test\s+(content|text|image)/gi,
  /sample\s+(data|text)/gi,
  /dummy\s+(data|text)/gi,
  /coming\s+soon/gi,
  /under\s+construction/gi,
  /asdf+/gi
];

async function scanFile(filePath) {
  const content = await fs.readFile(filePath, 'utf-8');
  const issues = [];
  
  PLACEHOLDER_PATTERNS.forEach(pattern => {
    let match;
    while ((match = pattern.exec(content)) !== null) {
      const lineNumber = content.substring(0, match.index).split('\n').length;
      issues.push({
        file: filePath,
        line: lineNumber,
        match: match[0]
      });
    }
  });
  
  return issues;
}

async function main() {
  const issues = await scanDirectory('./src');
  
  if (issues.length > 0) {
    console.error('❌ Виявлено placeholder текст:\n');
    issues.forEach(issue => {
      console.error(`  ${issue.file}:${issue.line}`);
      console.error(`    Знайдено: "${issue.match}"\n`);
    });
    process.exit(1);
  }
  
  console.log('✅ Placeholder текст не знайдено');
}
```

const puppeteer = require('puppeteer');

class SPASEOValidator {
  async validate(url) {
    const browser = await puppeteer.launch();
    const page = await browser.newPage();
    await page.goto(url, { waitUntil: 'networkidle0' });
    await page.waitForTimeout(2000);
    
    const html = await page.content();
    const issues = [];
    
    // Title перевірка
    const title = await page.title();
    if (!title || title.length < 30 || title.length > 60) {
      issues.push({
        type: 'meta',
        message: `Довжина title ${title.length} символів (оптимально: 30-60)`
      });
    }
    
    // Meta description
    const description = await page.$eval(
      'meta[name="description"]', 
      el => el.content
    ).catch(() => null);
    
    if (!description || description.length < 120 || description.length > 160) {
      issues.push({
        type: 'meta',
        message: 'Meta description відсутній або неоптимальної довжини'
      });
    }
    
    // H1 перевірка
    const h1Count = await page.$$eval('h1', h1s => h1s.length);
    if (h1Count === 0) {
      issues.push({ type: 'heading', message: 'Відсутній H1 тег' });
    } else if (h1Count > 1) {
      issues.push({ 
        type: 'heading', 
        message: `Знайдено ${h1Count} H1 тегів. Використовуйте лише один H1` 
      });
    }
    
    await browser.close();
    return issues;
  }
}

### Readability analysis

Flesch Reading Ease та Flesch-Kincaid Grade Level для оцінки складності тексту.

```javascript
// readability-checker.js
const { syllable } = require('syllable');

class ReadabilityAnalyzer {
  calculateFleschReadingEase(text) {
    const words = this.countWords(text);
    const sentences = this.countSentences(text);
    const syllables = this.countSyllables(text);
    
    const score = 206.835 - 
      (1.015 * (words / sentences)) - 
      (84.6 * (syllables / words));
    
    return Math.max(0, Math.min(100, score));
  }
  
  calculateGradeLevel(text) {
    const words = this.countWords(text);
    const sentences = this.countSentences(text);
    const syllables = this.countSyllables(text);
    
    return (0.39 * (words / sentences)) + 
           (11.8 * (syllables / words)) - 
           15.59;
  }
  
  countWords(text) {
    return text.split(/\s+/).filter(word => word.length > 0).length;
  }
  
  countSentences(text) {
    return text.split(/[.!?]+/).filter(s => s.trim().length > 0).length;
  }
  
  countSyllables(text) {
    const words = text.split(/\s+/);
    return words.reduce((total, word) => total + syllable(word), 0);
  }
}
```
