# Monitoring та Maintenance для Mobile First HTML Single Page розробки

## Вступ: комплексна стратегія моніторингу

**Дослідження охоплює п'ять критично важливих підетапів моніторингу та підтримки Mobile First HTML Single Page додатків станом на 2024-2025 роки.** Всі рекомендації базуються на актуальних джерелах, включають готові до використання конфігурації та враховують специфіку мобільної розробки з акцентом на приватність, продуктивність та автоматизацію.

Ключові виклики Mobile First SPA моніторингу включають soft-навігацію без перезавантаження сторінок, динамічний AJAX-контент, залежність від JavaScript execution та критичну важливість продуктивності на мобільних пристроях. Це дослідження надає практичні рішення для кожного виклику.

## 7.5.2 Performance Monitoring: оптимізація швидкодії

### RUM vs Synthetic моніторинг

**Real User Monitoring (RUM)** - пасивний моніторинг реальних користувачів у продакшені, покриває всі пристрої, браузери, мережі та географії. Найкраще для довгострокових трендів та кореляції з бізнес-метриками.

**Synthetic Monitoring** - активний моніторинг з симульованими користувачами у контрольованому середовищі за розкладом. Найкраще для regression testing, pre-production та конкурентного benchmarking.

**Рекомендація:** Використовуйте обидва разом - synthetic для контрольованого тестування, RUM для валідації у продакшені.

### Core Web Vitals 2024: INP замінив FID

**Ключова зміна:** 12 березня 2024 року INP (Interaction to Next Paint) замінив FID як Core Web Vital. INP вимірює ВСІ взаємодії (не лише першу) та включає повний lifecycle: input delay + processing time + presentation delay.

**Актуальні Core Web Vitals (2024-2025):**

1. **LCP (Largest Contentful Paint)** - Завантаження
   - Добре: ≤ 2.5s | Потребує покращення: 2.5-4s | Погано: > 4s

2. **INP (Interaction to Next Paint)** - Інтерактивність
   - Добре: ≤ 200ms | Потребує покращення: 200-500ms | Погано: > 500ms

3. **CLS (Cumulative Layout Shift)** - Візуальна стабільність
   - Добре: ≤ 0.1 | Потребує покращення: 0.1-0.25 | Погано: > 0.25

**Attribution build (розширене відлагодження):**

```html
<script type="module">
  import {onCLS, onINP, onLCP} from 'https://unpkg.com/web-vitals@5/dist/web-vitals.attribution.js?module';
  
  function sendDebugData({name, value, rating, id, attribution}) {
    const eventParams = {value, rating, metric_id: id};
    
    switch (name) {
      case 'INP':
        eventParams.target = attribution.interactionTarget;
        eventParams.interaction_type = attribution.interactionType;
        eventParams.input_delay = attribution.inputDelay;
        eventParams.processing_duration = attribution.processingDuration;
        eventParams.presentation_delay = attribution.presentationDelay;
        eventParams.load_state = attribution.loadState;
        break;
      case 'LCP':
        eventParams.element = attribution.element;
        eventParams.ttfb = attribution.timeToFirstByte;
        eventParams.resource_load_delay = attribution.resourceLoadDelay;
        eventParams.render_delay = attribution.elementRenderDelay;
        break;
      case 'CLS':
        eventParams.target = attribution.largestShiftTarget;
        eventParams.shift_time = attribution.largestShiftTime;
        break;
    }
    
    gtag('event', name, eventParams);
  }

  onINP(sendDebugData);
  onLCP(sendDebugData);
</script>
```

### JavaScript Error Tracking Best Practices

**Глобальні обробники помилок:**

```javascript
// Window Error Handler
window.onerror = function(message, source, lineno, colno, error) {
  Sentry.captureException(error || new Error(message), {
    contexts: {
      error_details: { message, source, lineno, colno }
    }
  });
  return false;
};

// Unhandled Promise Rejection Handler
window.addEventListener('unhandledrejection', (event) => {
  console.warn('Unhandled promise rejection:', event.reason);
  Sentry.captureException(event.reason || new Error('Unhandled Promise Rejection'), {
    contexts: {
      promise: { promise: event.promise }
    }
  });
});
```

**React Error Boundary:**

```javascript
import * as Sentry from "@sentry/react";
import { Component } from "react";

class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false };
  }

  static getDerivedStateFromError(error) {
    return { hasError: true };
  }

  componentDidCatch(error, errorInfo) {
    Sentry.withScope((scope) => {
      scope.setContext("errorBoundary", {
        componentStack: errorInfo.componentStack
      });
      Sentry.captureException(error);
    });
  }

  render() {
    if (this.state.hasError) {
      return <h1>Щось пішло не так.</h1>;
    }
    return this.props.children;
  }
}
```

```javascript
    // Видалити user PII
    if (event.user) {
      delete event.user.email;
      delete event.user.username;
      event.user.ip_address = null;
    }
    
    // Очистити request data
    if (event.request) {
      delete event.request.cookies;
      delete event.request.headers;
      if (event.request.url) {
        event.request.url = event.request.url.split('?')[0];
      }
    }
    
    // Видалити sensitive extras
    if (event.extra) {
      delete event.extra.sessionToken;
      delete event.extra.apiKey;
    }
    
    return event;
  },
  
  // Scrub breadcrumbs
  beforeBreadcrumb(breadcrumb, hint) {
    // Видалити input values
    if (breadcrumb.category === 'ui.input') {
      delete breadcrumb.message;
    }
    
    // Видалити request/response data
    if (breadcrumb.category === 'fetch') {
      delete breadcrumb.data?.request_body;
      delete breadcrumb.data?.response_body;
    }
    
    return breadcrumb;
  },
  
  // Вимкнути автозбір PII
  sendDefaultPii: false,
  
  // Session Replay приватність
  integrations: [
    Sentry.replayIntegration({
      maskAllText: true,
      blockAllMedia: true,
      privacy: {
        maskTextSelector: "[data-sensitive]",
        blockSelector: "[data-private]"
      }
    })
  ]
});
```

### Unified Monitoring Dashboard

**Інтеграція декількох систем моніторингу:**

```javascript
// Централізована система збору метрик
class MonitoringHub {
  constructor() {
    this.sentry = Sentry;
    this.analytics = gtag;
    this.performance = null;
  }

  async initialize() {
    // Ініціалізація Sentry
    this.sentry.init({ /* config */ });
    
    // Ініціалізація Performance Monitoring
    const { onCLS, onINP, onLCP } = await import('web-vitals');
    
    onCLS(this.handleMetric.bind(this));
    onINP(this.handleMetric.bind(this));
    onLCP(this.handleMetric.bind(this));
  }

  handleMetric(metric) {
    // Надіслати до Analytics
    this.analytics('event', metric.name, {
      value: metric.value,
      metric_id: metric.id,
      metric_rating: metric.rating
    });
    
    // Надіслати до Sentry (якщо погано)
    if (metric.rating === 'poor') {
      this.sentry.captureMessage(`Poor ${metric.name}: ${metric.value}`, {
        level: 'warning',
        tags: { metric_type: 'web-vital' }
      });
    }
  }

  trackError(error, context) {
    // Sentry для detailed error tracking
    this.sentry.captureException(error, context);
    
    // Analytics для бізнес-метрик
    this.analytics('event', 'exception', {
      description: error.message,
      fatal: false
    });
  }
}

// Використання
const monitoring = new MonitoringHub();
await monitoring.initialize();
```

## Висновки та ключові takeaways

**Критичні insights для 2024-2025:**

1. **INP замінив FID** (березень 2024) - необхідно переналаштувати моніторинг інтерактивності для відстеження всіх взаємодій, а не тільки першої

2. **Mobile First обов'язковий** - тестуйте на Slow 3G (2s latency) для inclusive design, використовуйте mobile throttling за замовчуванням

3. **Privacy-first моніторинг** - GDPR compliance з першого дня, data scrubbing, cookie consent, user deletion workflows

4. **Trunk-Based Development** показує 12.8x кращу продуктивність (DORA 2024) - короткі feature branches, часта інтеграція

5. **Автоматизація критична** - Dependabot/Renovate для dependencies, security scanning у CI/CD, automated rollback, performance budgets

6. **RUM + Synthetic разом** - synthetic ловить регресії перед продакшеном, RUM показує реальний досвід користувачів

7. **Sampling для контролю costs** - 5-10% error sampling, 10% trace sampling, 100% replay при помилках

8. **Zero-downtime deployments** - blue-green або canary strategies, automated health checks, instant rollback capability

9. **Technical debt = 20-30% capacity** - регулярне виділення часу на зменшення боргу, трекінг метрик щокварталу

10. **Інтеграція між tools** - централізований monitoring hub, unified alerting, automated workflows між системами
