## 🎯 EXECUTIVE SUMMARY

Core Web Vitals стали критичним фактором успіху у 2024-2025, безпосередньо впливаючи на SEO rankings та бізнес-метрики. Дослідження показує, що оптимізація CWV призводить до **33-61% зростання конверсії**, **26-53% збільшення revenue per visitor**, та **15-76% зменшення bounce rate**. У березні 2024 Google замінив FID на INP (Interaction to Next Paint) - більш всеосяжну метрику відгуку. Для Mobile First Single Page Applications критично важливі Server-Side Rendering, агресивна оптимізація зображень та правильна пріоритизація ресурсів для досягнення цільових показників: **LCP <2.5s, INP <200ms, CLS <0.1**.

## 🔑 КЛЮЧОВІ ЗНАХІДКИ

### 1. INP замінив FID як Core Web Vital (березень 2024)
Нова метрика вимірює ВСІ взаємодії користувача, а не лише першу. Це потребує оптимізації всіх event handlers, розбиття довгих tasks та ефективного управління JavaScript execution.

### 2. SPAs мають унікальні виклики для CWV
Середній Lighthouse score для SPA - лише 24/100. Core Web Vitals вимірюються тільки для landing pages, що робить SSR/SSG критично важливим для першого завантаження.

### 3. Mobile-first не опція - це необхідність
60%+ трафіку походить з мобільних пристроїв. Google використовує mobile-first indexing. 3G мережі додають 200-1000ms затримки на кожну зміну RRC стану, а мобільні пристрої в 3-5 разів повільніші за desktop.

### 4. Реальні дані (Field Data) визначають rankings
Тільки CrUX field data впливає на SEO. Lab data корисна для розробки, але не впливає на rankings. Оцінка базується на 75th percentile реальних користувачів з 28-денною затримкою.

### 5. LCP субчастини дозволяють точну діагностику (Chrome 129+)
LCP тепер розбивається на 4 компоненти: TTFB (~40%), Resource Load Delay (~0%), Resource Load Duration (~40%), Element Render Delay (~0%), що дозволяє точно ідентифікувати bottlenecks.

### 6. AVIF формат зображень досяг 93.8% browser support
Забезпечує 50% меншi розміри порівняно з JPEG, 25% менші за WebP. Real impact: зменшення з 1MB до 404KB (desktop) та з 430KB до 124KB (mobile).

### 7. CLS prevention потребує holistic approach
79% mobile pages досягають good CLS у 2024. Критичні техніки: explicit dimensions для всіх media, `font-display: optional` для fonts, skeleton screens з правильними dimensions, reserved space для ads/dynamic content.

### 8. Accessibility та Performance синергічні
ADA Title II Final Rule (квітень 2024) вимагає WCAG 2.1 Level AA compliance. Semantic HTML, proper image sizing, progressive enhancement покращують обидва аспекти одночасно.

### 9. Performance budgets запобігають regressions
Встановлення budgets у CI/CD pipeline: LCP <2.5s, INP <200ms, CLS <0.1, initial JavaScript <50KB gzipped, total page size <500KB mobile.

### 10. Web Vitals library v5.0+ з attribution build
Надає детальний breakdown кожної метрики для debugging: LCP subparts, INP component timing, CLS element identification. Всього ~3.5KB gzipped для attribution version.

## ⭐ BEST PRACTICES

### Practice 1: Оптимізація LCP через Priority Hints та Preloading

**Що робити:** Використовуйте `fetchpriority="high"` для LCP image та `<link rel="preload">` для критичних ресурсів.

**Чому це працює:** Preload scanner виявляє ресурси раніше, priority hints вказують пріоритети. Усуває Resource Load Delay, прискорює LCP на 500-1300ms.

**Mobile First специфіка:** На мобільних мережах кожна мілісекунда критична через high latency.

**Код:**
```html
<head>
  <link rel="preconnect" href="https://cdn.example.com" crossorigin>
  <link rel="preload" as="image" href="/hero-mobile.avif" 
        type="image/avif" fetchpriority="high">
  <style>
    .hero{width:100%;min-height:60vh}
    .hero-img{width:100%;height:100%;object-fit:cover}
  </style>
</head>
<body>
  <picture>
    <source type="image/avif" srcset="/hero-mobile.avif 400w, /hero-desktop.avif 1200w">
    <img src="/hero-desktop.jpg" width="1200" height="800" 
         fetchpriority="high" alt="Hero">
  </picture>
</body>
```

### Practice 2: INP Optimization через Task Yielding

**Що робити:** Розбивайте довгі tasks (>50ms) на chunks з yielding.

**Чому працює:** INP вимірює час до visual update. Довгі tasks блокують main thread. Yielding дозволяє обробляти interactions.

**Mobile специфіка:** Мобільні CPU в 3-5 разів повільніші, tasks триваліші.

**Код:**
```javascript
// Task yielding
async function processLargeDataset(items) {
  const CHUNK_SIZE = 50;
  for (let i = 0; i < items.length; i += CHUNK_SIZE) {
    const chunk = items.slice(i, i + CHUNK_SIZE);
    chunk.forEach(item => performCalculation(item));
    await new Promise(resolve => setTimeout(resolve, 0));
  }
}

// Event handler optimization
button.addEventListener('click', async () => {
  button.classList.add('processing');
  await new Promise(resolve => setTimeout(resolve, 0));
  await processLargeDataset(data);
  button.classList.remove('processing');
});
```

### Practice 3: CLS Prevention через Explicit Dimensions

**Що робити:** Встановлюйте width/height для images, використовуйте aspect-ratio, резервуйте space.

**Чому працює:** Браузер розраховує потрібний простір до завантаження, запобігаючи shifts.

**Mobile специфіка:** Shifts більш помітні на малих viewports.

**Код:**
```html
<img src="product.jpg" width="800" height="600" alt="Product">
<style>
  img { width: 100%; height: auto; }
  .video-container { aspect-ratio: 16/9; width: 100%; }
  .ad-slot { min-height: 250px; }
</style>
```

### Practice 4: Font Loading з font-display та Fallback Matching

**Що робити:** Використовуйте `font-display: optional`, preload fonts, створюйте matched fallbacks.

**Чому працює:** `optional` показує fallback якщо font не завантажився за 100ms, усуваючи CLS.

**Mobile специфіка:** На 3G fonts завантажуються 3-10 секунд.

**Код:**
```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-var.woff2") format("woff2-variations");
  font-display: optional;
}
@font-face {
  font-family: "Inter-fallback";
  size-adjust: 107.2%;
  ascent-override: 90%;
  src: local("Arial");
}
body { font-family: "Inter", "Inter-fallback", sans-serif; }
```

### Practice 5: TTFB Optimization через Server Strategies

**Що робити:** CDN, compression (Brotli/Gzip), caching, 103 Early Hints, SSR/SSG.

**Чому працює:** TTFB ~40% LCP. Оптимізація server response прямо впливає на LCP.

**Mobile специфіка:** 3G: 200ms latency, 4G: 100ms. CDN критично важливий.

**Код:**
```nginx
brotli on;
brotli_comp_level 6;
gzip on;
location ~* \.(js|css|png|jpg|webp|avif)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

### Practice 6: SPA через SSR/SSG

**Що робити:** Server-Side Rendering, progressive hydration, code splitting.

**Чому працює:** Client-only додає 3-7s до LCP. SSR delivery HTML негайно.

**Mobile специфіка:** Мобільні slower в JS parsing/execution.

**Код:**
```javascript
// Next.js SSR
export async function getServerSideProps() {
  const data = await fetch('https://api.example.com/data').then(r => r.json());
  return { props: { data } };
}

// Code splitting
const HeavyComponent = lazy(() => import('./HeavyComponent'));
```

### Practice 7: Adaptive Loading для Networks

**Що робити:** Network Information API для адаптації під connection quality.

**Чому працює:** Різні користувачі мають різну якість. 3G не можуть завантажити heavy content швидко.

**Mobile специфіка:** Мобільні переключаються WiFi/4G/3G.

**Код:**
```javascript
function getConnectionQuality() {
  const conn = navigator.connection;
  if (!conn) return 'high';
  const { effectiveType, saveData } = conn;
  if (saveData) return 'low';
  if (effectiveType === '3g') return 'medium';
  return 'high';
}

function getOptimalImage(url) {
  const quality = getConnectionQuality();
  const configs = {
    low: { format: 'jpg', width: 400 },
    medium: { format: 'webp', width: 800 },
    high: { format: 'avif', width: 1200 }
  };
  const config = configs[quality];
  return `${url}?format=${config.format}&w=${config.width}`;
}
```

## 💻 CODE SNIPPETS & TEMPLATES

### Complete Web Vitals Monitoring

```javascript
import { onCLS, onINP, onLCP } from 'web-vitals/attribution';

const queue = new Set();

function handleMetric({ name, value, rating, attribution }) {
  const metric = {
    name, value, rating,
    url: location.href,
    connection: navigator.connection?.effectiveType
  };
  
  switch (name) {
    case 'LCP':
      metric.attribution = {
        element: attribution.element,
        ttfb: attribution.timeToFirstByte,
        resourceLoadDelay: attribution.resourceLoadDelay
      };
      break;
    case 'INP':
      metric.attribution = {
        target: attribution.interactionTarget,
        inputDelay: attribution.inputDelay,
        processingDuration: attribution.processingDuration
      };
      break;
    case 'CLS':
      metric.attribution = {
        target: attribution.largestShiftTarget,
        time: attribution.largestShiftTime
      };
      break;
  }
  
  queue.add(metric);
  setTimeout(flushQueue, 5000);
}

function flushQueue() {
  if (queue.size === 0) return;
  const body = JSON.stringify([...queue]);
  navigator.sendBeacon('/analytics', body);
  queue.clear();
}

onLCP(handleMetric);
onINP(handleMetric);
onCLS(handleMetric);

addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') flushQueue();
});
```

## ⚠️ ТИПОВІ ПОМИЛКИ

### LCP Помилки

**#1: Lazy-loading LCP image**
```html
<!-- ❌ BAD --> <img loading="lazy">
<!-- ✅ GOOD --> <img loading="eager" fetchpriority="high">
```
Проблема: +1.3s затримка

**#2: JS-rendered LCP**
Проблема: +3-7s через waterfall
Рішення: SSR/SSG з LCP в HTML

**#3: Background-image як LCP**
Проблема: +1s, не видимий для preload scanner
Рішення: `<img>` замість CSS background

**#4: Cross-origin без preconnect**
Проблема: +500ms
Рішення: `<link rel="preconnect">`

### INP Помилки

**#5: Довгі tasks**
```javascript
// ❌ BAD - blocks thread
for (let i = 0; i < 1000000; i++) calculate(i);

// ✅ GOOD - yields
for (let i = 0; i < 1000000; i += 1000) {
  chunk.forEach(calculate);
  await new Promise(r => setTimeout(r, 0));
}
```

**#6: Third-party scripts блокують**
Рішення: `async`/`defer` attributes, delayed loading

**#7: Не оптимізовані event handlers**
Рішення: Throttle/debounce, passive listeners

### CLS Помилки

**#8: Images без dimensions**
```html
<!-- ❌ BAD --> <img src="x.jpg">
<!-- ✅ GOOD --> <img src="x.jpg" width="800" height="600">
```

**#9: font-display: block**
Рішення: `font-display: optional`

**#10: Dynamic content insertion**
Рішення: Fixed positioning або reserved space

**#11: Ads без space**
Рішення: `min-height` для ad slots

**#12: Animating layout properties**
```css
/* ❌ BAD */ animation: left 0.3s;
/* ✅ GOOD */ animation: transform 0.3s;
```

### TTFB Помилки

**#13: No compression**
Рішення: Enable Brotli/Gzip (70-80% savings)

**#14: Poor caching**
```http
# ❌ BAD: Cache-Control: no-cache
# ✅ GOOD: Cache-Control: public, max-age=31536000, immutable
```

**#15: No CDN**
Рішення: CDN зменшує latency 100-300ms

## 📈 PERFORMANCE CONSIDERATIONS

### Trade-offs Between Metrics

**LCP vs CLS:** Large images швидко (good LCP) можуть спричинити shifts (bad CLS). **Рішення:** Explicit dimensions.

**LCP vs INP:** Preloading LCP може затримати JS. **Рішення:** Code splitting, selective fetchpriority.

**JavaScript Bundle Size:** More features = larger bundles = slower TTI. **Баланс:** Route-based splitting, lazy loading.

### Mobile Challenges

**Network Impact:**
- 3G: +200-1000ms latency per RRC transition
- 4G: +100ms baseline latency
- Strategy: Aggressive compression, adaptive loading

**CPU Constraints:**
- Mobile 3-5x slower than desktop
- Heavy JS parsing critical
- Solution: SSR, smaller bundles

**Battery Consumption:**
- Each network request = ~10 joules
- Minimize polling frequency
- Batch API requests

### Balancing Metrics

**Priority Order:**
1. Fix "Poor" metrics first (biggest SEO impact)
2. Improve to "Good" thresholds
3. Further optimization (diminishing returns)

**When Conflicts Arise:**
- User experience > perfect scores
- Mobile performance > desktop
- Core functionality > enhancements

- Battery-conscious patterns

**Continuous monitoring:**
- Real User Monitoring (RUM) в production
- Performance budgets у CI/CD
- Regular audits та A/B testing
- Track business metrics correlation

**Holistic approach:**
- Balance між metrics (LCP, INP, CLS)
- Integrate accessibility (WCAG 2.1 AA)
- Progressive enhancement patterns
- Team performance culture
