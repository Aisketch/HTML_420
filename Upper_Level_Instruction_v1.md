## 🎓 CORE PRINCIPLES (My Foundation)

### 1. PARETO PRINCIPLE (80/20) ⭐ PRIORITY #1

**Philosophy:** 20% of approaches solve 80% of problems.

**In Practice:**
- **Core 5 Files** cover 60% of all projects
- **Simple solutions first**, add complexity only when justified
- **Vanilla before libraries** (Alpine.js only if needed, no jQuery ever)
- **2-4 breakpoints max** (not 6-8)
- **Focus on high-impact optimizations** (LCP, CLS) not minor tweaks

**Pareto in Action:**
```
QUESTION: "Should I use Tailwind or custom CSS?"
PARETO ANSWER: 
- Small project (<5 components)? → Custom CSS (simpler)
- Large project (10+ components)? → Tailwind (scales better)
- Justification required for every framework choice
```

---

### 2. SIMPLICITY FIRST ⭐ PRIORITY #2

**Philosophy:** Readable code > Clever code. Maintainable > Innovative.

**Rules:**
✅ **DO:**
- Use semantic HTML5 (`<section>`, `<article>`, `<nav>`)
- Write vanilla JS when possible
- Inline critical CSS (<14KB)
- Clear class names (BEM or utility)
- Comments for "why", not "what"

❌ **AVOID:**
- Complex build systems for simple pages
- JavaScript frameworks for static content
- Excessive abstraction
- Premature optimization
- Over-engineering

**Simplicity Test:**
```
Can a developer understand this code in 2 minutes?
├─ YES → Ship it ✅
└─ NO → Simplify or justify complexity
```

---

### 3. MOBILE FIRST ALWAYS ⭐ PRIORITY #3

**Philosophy:** Design for 375px, enhance for larger screens.

**Approach:**
1. **Start:** Mobile design (375px - 640px)
2. **Enhance:** Tablet layout (641px - 1024px)
3. **Optimize:** Desktop experience (1025px+)
4. **Test:** Real devices, not just DevTools

**Mobile First Checklist:**
- [ ] Touch targets 44x44px minimum
- [ ] Font size 16px+ (no zoom on input)
- [ ] Tap-friendly navigation
- [ ] Fast load on 3G (<3s LCP)
- [ ] Thumb-zone optimized layout
